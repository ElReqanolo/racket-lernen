1.1 DrRacket bedienen

DrRacket ist eine Entwicklungsumgebung: ein Programm, mit dem du Programme schreibst, ausführst und untersuchst. Das Fenster hat zwei Hälften.

TeilWofürGut zu wissen
Definitionsfenster (oben, „Editor“)Hier steht dein Programm.Wird gespeichert (Dateiendung .rkt). Erst nach Start wird es ausgeführt.
Interaktionsfenster / REPL (unten)Ausdrücke eintippen und sofort das Ergebnis sehen; zeigt auch Ausgaben und Fehler.Nichts wird gespeichert. Bei jedem Start wird die REPL geleert.

REPL steht für Read-Eval-Print-Loop: DrRacket liest deinen Ausdruck, wertet ihn aus, druckt das Ergebnis und wartet dann (Schleife) auf den nächsten.

1.2 Ausdrücke und Zahlen

Ein Ausdruck ist ein Stück Programm, das einen Wert liefert. Ausdrücke, die etwas ausrechnen, haben immer dieselbe Form:

(Operator Operand ...)

  • Klammer auf – hier beginnt der Ausdruck.

  • Operator – bestimmt, was gemacht wird (die Operation), z. B. +.

  • Operanden – die Eingaben für die Operation. Davon kann es mehrere geben.

  • Klammer zu – hier endet der Ausdruck.

Diese Schreibweise heißt Präfix-Notation (Operator vorne). Sie wirkt erst ungewohnt, hat aber Vorteile: Es gibt keine Punkt-vor-Strich-Regeln, und ein Operator kann beliebig viele Operanden haben.

Die vier Grundrechenarten

AusdruckErgebnisVorlesen als
(+ 123 42)165„Die Summe von 123 und 42“
(- 123 42)81„Die Differenz von 123 und 42“
(* 123 42)5166„Das Produkt von 123 und 42“
(/ 123 42)2.9285714… (Periode 285714)„Der Quotient von 123 und 42“
(+ 1 2 3 4)10mehrere Operanden sind erlaubt (Extra)

Vorlesen hilft: Das Buch empfiehlt, Ausdrücke laut zu lesen – (* 123 (+ 20 22)) ist „das Produkt von 123 und der Summe von 20 und 22“.

Zur Division: DrRacket rechnet in der Lehrsprache mit Brüchen exakt. Ein Ergebnis wie 123/42 wird als periodische Dezimalzahl angezeigt (die Periode wird überstrichen), nicht gerundet. Du kannst Brüche auch direkt schreiben: 3/2 ist die Zahl 1,5. Kommazahlen schreibt man mit Punkt: 5.5.

Verschachteln (Kombinieren)

Ein Operand darf selbst wieder ein Ausdruck sein. Wichtig: Um jeden Teilausdruck gehört ein eigenes Klammerpaar.

(* 123 (+ 20 22))          ; => 5166
(* 123 (+ (* 2 10) 22))    ; => 5166

So rechnet DrRacket den zweiten Ausdruck aus – immer die innersten Klammern zuerst:

  1. (* 2 10) → 20, also (* 123 (+ 20 22))

  2. (+ 20 22) → 42, also (* 123 42)

  3. (* 123 42) → 5166

Mathe → Racket übersetzen

(23 + 42) · (12 + 14 · 2)(* (+ 23 42) (+ 12 (* 14 2)))

Typische Fehler: (123 + 42) (Operator in der Mitte) → Fehlermeldung „Operator darf keine Zahl sein, ist aber 123“. Fehlendes Leerzeichen: (+1 2) liest DrRacket als Operator +1. Zusätzliche Klammern wie ((+ 1 2)) sind nicht harmlos – jede Klammer bedeutet „anwenden“.

1.3 Definitionen und Variablen

Mit define gibst du einem Wert einen Namen. Danach kannst du den Namen überall statt des Werts benutzen.

(define name ausdruck)

Beispiele aus dem Buch

(define alles (+ 20 22))
(define one 1)
(define temperature 23)
(define birgit-prinz 9)   ; Bindestriche in Namen sind erlaubt

Nach Start liefert alles in der REPL 42.

Was dabei passiert: DrRacket rechnet zuerst den Ausdruck (+ 20 22) aus und bindet dann den Namen alles an das Ergebnis 42. Der Name merkt sich also den Wert, nicht die Rechnung.

Begriffe

BegriffBedeutungBeispiel
Literalein Wert, der direkt so hingeschrieben ist23, 5.5, "Mike"
Variableein Name, der für einen Wert stehtalles, temperature
Definitiondie Bindung eines Namens an einen Wert mit define(define one 1)

Wichtig: In Racket ändert sich der Wert einer Variablen nicht. (define one 1) bedeutet nicht „Speicherplatz, in dem gerade 1 steht“, sondern „one ist 1“ – wie in der Mathematik. Einen Namen ein zweites Mal zu definieren, führt zu einem Fehler.

Regeln für Namen (laut Racket-Handbuch): Ein Name darf keine Leerzeichen enthalten und keins dieser Zeichen: Anführungszeichen, Komma, Apostroph, Backtick, runde, eckige oder geschweifte Klammern, senkrechter Strich, Semikolon, Raute (#). Bindestriche, Umlaute, ?, !, -> usw. sind erlaubt. Gute Namen beschreiben, wofür der Wert steht: temperatur statt t.

Definitionsfenster und REPL zusammen: Definitionen stehen im Definitionsfenster. Nach Start kannst du sie in der REPL benutzen, z. B. (* alles 2) → 84. Tippst du einen Namen ein, der nicht definiert ist, meldet DrRacket: „a: Variable ist nicht definiert“.

Kommentare: Alles hinter einem Semikolon ; bis zum Zeilenende ignoriert DrRacket. Damit schreibst du Erklärungen für Menschen ins Programm.

1.4 Rechnen ohne Zahlen: Zeichenketten

Zeichenketten (englisch Strings) stellen Text dar. Man schreibt sie in doppelte Anführungszeichen: "Herbert", "Mike ist doof", "" (leere Zeichenkette). Leerzeichen innerhalb der Anführungszeichen gehören zum Text. Ein Anführungszeichen im Text schreibst du mit Backslash davor: "Er sagte \"Hallo\"".

Die Befehle für Zeichenketten

BefehlWas er tutBeispielErgebnis
string-appendhängt zwei oder mehr Zeichenketten aneinander(string-append "Herbert" "Mike")"HerbertMike"
Leerzeichen musst du selbst einfügen(string-append "Mike" " " "ist doof")"Mike ist doof"
string-lengthzählt die Zeichen (auch Leerzeichen)(string-length "Herbert")7
(string-length "Mike")4
string->numbermacht aus Text eine Zahl(string->number "23")23
number->stringmacht aus einer Zahl Text(number->string 23)"23"

Wie man die Namen liest: string->number ist ein einziger Name (keine Rechnung!). Der Pfeil -> bedeutet „wird zu“: „String wird zu Zahl“. In Racket dürfen Namen Bindestriche, Pfeile, Fragezeichen usw. enthalten. Solche eingebauten Funktionen kannst du benutzen, ohne sie selbst zu definieren.

Zahl oder Zeichenkette – der wichtige Unterschied

23 ist eine Zahl, "23" ist Text, der zufällig aus den Zeichen 2 und 3 besteht. DrRacket hält beides streng auseinander:

AusdruckWas passiert
(+ "23" 42)Fehler: + braucht Zahlen
(string-append 23 "42")Fehler: string-append braucht Zeichenketten
(number->string "23")Fehler: "23" ist schon Text
(+ (string->number "23") 42)65 – erst umwandeln, dann rechnen
(string-append (number->string 23) "42")"2342"

Kombinieren: Auch hier darf ein Operand ein Ausdruck sein.

(string-length (string-append "Mike" " " "ist doof"))   ; => 13
(string-append "Ergebnis: " (number->string (* 6 7)))   ; => "Ergebnis: 42"

Extra (aus dem Racket-Handbuch zur Anfängersprache): string=? vergleicht zwei Zeichenketten ((string=? "a" "a") → #t), string<? prüft die alphabetische Reihenfolge, string->strings-list zerlegt Text in einzelne Zeichen. Die braucht ihr später.

1.4 Rechnen ohne Zahlen: Bilder erzeugen

Mit dem Teachpack image.rkt kann DrRacket mit Bildern rechnen – genauso wie mit Zahlen. Ein Bild ist ein ganz normaler Wert: Man kann es berechnen, mit define benennen und an Funktionen übergeben. Die Bildbefehle entsprechen dem Racket-Bildpaket 2htdp/image; deren Doku ist hier die Zusatzquelle.

Fast alle Formen haben dasselbe Muster: zuerst die Größe(n), dann der Modus, dann die Farbe.

(square 40 "solid" "red")
;       │    │       └─ Farbe
;       │    └─ Modus: gefüllt oder nur Umriss
;       └─ Größe: Seitenlänge in Pixeln

1.4 Rechnen ohne Zahlen: Bilder kombinieren

Das Spannende: Bildbefehle bekommen Bilder als Eingabe und liefern ein neues Bild. Die Originale bleiben unverändert.

Die beiden Befehle aus dem Buch

BefehlWas er tutAusrichtung
besidesetzt Bilder nebeneinander (von links nach rechts)an der waagerechten Mittellinie
abovesetzt Bilder übereinander (von oben nach unten)an der senkrechten Mittellinie

Beide nehmen zwei oder mehr Bilder: (beside s1 p1 c1) setzt drei Bilder in eine Reihe.

Schritt 1: Drei Bilder herstellen und benennen

Um mit Bildern zu üben, brauchen wir erst einmal ein paar Bilder. Wir erzeugen drei Formen und geben jeder mit define einen kurzen Namen. Die Namen sind frei gewählt: s steht für square (Quadrat), c für circle (Kreis), p für polygon (Stern-Vieleck). Die 1 heißt einfach „Bild Nummer 1 dieser Sorte“.

(define s1 (square 40 "solid" "red"))               ; s1 = rotes, gefülltes Quadrat, 40 Pixel Seitenlänge
(define c1 (circle 40 "solid" "green"))             ; c1 = grüner, gefüllter Kreis, Radius 40 (also 80 Pixel breit)
(define p1 (star-polygon 20 10 3 "solid" "blue"))   ; p1 = blauer Stern mit 10 Zacken

Schreib diese drei Zeilen ins Definitionsfenster und drücke Start. Ab jetzt sind s1, c1 und p1 Variablen, die für ein Bild stehen. Tippst du in der REPL s1 ein, erscheint das rote Quadrat. Was square, circle und star-polygon genau machen, steht im Abschnitt „Bilder 1“.

NameSteht fürGröße
s1rotes Quadrat40 × 40 Pixel
c1grüner Kreis80 × 80 Pixel
p1blauer Stern (10 Zacken)etwas kleiner als der Kreis

Schritt 2: Die Bilder kombinieren

In den Skizzen steht Q für das Quadrat s1, K für den Kreis c1 und S für den Stern p1.

(beside s1 p1)
;  Ergebnis:  [Q][S]          Quadrat links, Stern rechts

(above s1 c1)
;  Ergebnis:  [Q]             Quadrat oben,
;             [K]             Kreis darunter

(above (beside s1 p1) (beside p1 c1))
;  Ergebnis:  [Q][S]          obere Reihe:  Quadrat, Stern
;             [S][K]          untere Reihe: Stern, Kreis

Der dritte Ausdruck zeigt: Ein Operand von above darf selbst ein Ausdruck sein, der ein Bild liefert. So baust du große Bilder aus kleinen. Ausgewertet wird von innen nach außen:

  1. (beside s1 p1) → die Reihe [Q][S]

  2. (beside p1 c1) → die Reihe [S][K]

  3. above stapelt beide Reihen übereinander.

Weil Kreis, Quadrat und Stern unterschiedlich groß sind, werden sie jeweils mittig zueinander ausgerichtet – das Raster ist also nicht ganz gleichmäßig.

Das Muster, das zu tile führt

Jetzt bauen wir zwei „Kachelmuster“ – jeweils zwei Bilder, die oben in einer Reihenfolge und unten umgekehrt stehen, wie bei einem Schachbrett:

(above
 (beside s1 p1)
 (beside p1 s1))
;  Ergebnis:  [Q][S]
;             [S][Q]

(above
 (beside p1 c1)
 (beside c1 p1))
;  Ergebnis:  [S][K]
;             [K][S]

Beide Ausdrücke liefern ein 2×2-Muster, bei dem die Bilder über Kreuz stehen.

Schau genau hin: Beide Ausdrücke sind gleich aufgebaut. Nur die beiden Bilder sind verschieden. Allgemein sieht das Muster so aus – mit a und b als Platzhalter:

(above
 (beside a b)
 (beside b a))

Genau dieses Muster wird im nächsten Abschnitt zur Funktion tile.

1.5 Abstraktion und Applikation: lambda und tile

Das ist der wichtigste Schritt in Kapitel 1: Aus einem Muster wird eine eigene Funktion.

Schritt 1 – Der naive Versuch. Man könnte das Muster einfach mit define benennen:

(define tile
  (above
   (beside a b)
   (beside b a)))

Beim Start meldet DrRacket: „a: Variable ist nicht definiert“. Klar: define rechnet den Ausdruck sofort aus – aber was a und b sind, steht nirgends. Sie sollen ja erst später eingesetzt werden.

Schritt 2 – Mit lambda. Genau dafür gibt es lambda. Es bedeutet: „Die Namen a und b sind Platzhalter – hier werden später (vielleicht mehrmals) Werte eingesetzt.“

(define tile
  (lambda (a b)          ; a und b sind die Parameter
    (above               ; ab hier: der Rumpf
     (beside a b)
     (beside b a))))

„To tile“ heißt auf Deutsch „kacheln“. Jetzt startet das Programm ohne Fehler, und du kannst tile benutzen:

Zur Erinnerung: Damit die folgenden Aufrufe funktionieren, müssen die drei Beispielbilder aus „Bilder 2“ im Definitionsfenster stehen:

(define s1 (square 40 "solid" "red"))               ; rotes Quadrat   (Q)
(define c1 (circle 40 "solid" "green"))             ; grüner Kreis    (K)
(define p1 (star-polygon 20 10 3 "solid" "blue"))   ; blauer Stern    (S)

Statt s1, c1 und p1 kannst du tile auch jedes andere Bild geben, zum Beispiel (tile (circle 10 "solid" "black") (square 20 "outline" "black")).

(tile s1 p1)   ; Kachelmuster aus Quadrat und Stern
(tile p1 c1)   ; Kachelmuster aus Stern und Kreis

Die Teile eines lambda-Ausdrucks

(lambda (a b)                    ; (lambda (p1 ... pn) e)
  (above (beside a b)            ;   p1 ... pn = Parameter
         (beside b a)))          ;   e         = Rumpf
BegriffWas es istBei tile
Abstraktionder lambda-Ausdruck im Programm(lambda (a b) ...)
Parameterdie Namen in der Klammer nach lambda – Platzhalter für die Eingabena, b
Rumpfder Ausdruck im Inneren, der das Ergebnis berechnet(above (beside a b) (beside b a))
Funktionder Wert, der beim Auswerten der Abstraktion herauskommt; erwartet für jeden Parameter eine Eingabeder Wert von tile
Applikation (auch Funktionsaufruf, Funktionsanwendung)ein Ausdruck in Klammern, der eine Funktion auf Eingaben anwendet(tile s1 p1)
Argumentedie Werte, die beim Aufruf für die Parameter eingesetzt werdendas Bild von s1 und das Bild von p1

Das Buch betont den Unterschied: Die Abstraktion ist der Text im Programm, die Funktion ist der Wert, der daraus entsteht. Im Alltag sagt man aber meist einfach „Funktion“.

So wertet DrRacket (tile s1 p1) aus – Schritt für Schritt

  1. Der Operator tile wird ausgewertet: Die Variable tile wird durch ihren Wert ersetzt, also den lambda-Ausdruck.

  2. Die Operanden werden ausgewertet: s1 wird zum roten Quadrat, p1 zum blauen Stern.

  3. Einsetzen (Substitution): Im Rumpf wird jedes a durch das Quadrat und jedes b durch den Stern ersetzt: (above (beside 🟥 ⭐) (beside ⭐ 🟥))

  4. Jetzt wird ganz normal von innen nach außen gerechnet: erst die beiden beside, dann above.

  5. Ergebnis: ein Bild mit Quadrat–Stern oben und Stern–Quadrat unten.

(Die Symbole 🟥 = rotes Quadrat s1 und ⭐ = blauer Stern p1 stehen hier nur für die Bilder – in DrRacket siehst du die echten Bilder. Das Ergebnis sieht so aus: oben [Q][S], unten [S][Q].)

Mit dem Stepper nachvollziehen: Schreib das tile-Programm samt (tile s1 p1) ins Definitionsfenster und klicke auf Stepper. Mit den Pfeilen gehst du vor und zurück. Links ist grün markiert, was als Nächstes ausgewertet wird, rechts siehst du das Ergebnis dieses Schritts. Achte besonders auf den Moment, in dem tile durch den lambda-Ausdruck ersetzt wird und dann a und b eingesetzt werden.

Funktionen lassen sich verschachteln: tile liefert ein Bild – und Bilder kann man wieder an tile geben:

(tile (tile s1 p1) c1)          ; große Kachel aus einer kleinen Kachel und dem Kreis
(tile (tile s1 p1) (tile p1 c1))

Eingebaute und eigene Funktionen funktionieren gleich: (+ 1 2), (beside s1 p1) und (tile s1 p1) sind alle Applikationen – Klammer, Operator, Operanden. Der einzige Unterschied: tile hast du selbst definiert.

Warum Abstraktion so wichtig ist

  • Weniger Wiederholung: Das Muster steht nur einmal im Programm.

  • Weniger Fehler: Willst du das Muster ändern, änderst du es an genau einer Stelle.

  • Verständlicher: (tile s1 p1) sagt, was passiert; der Rumpf sagt, wie.

Typische Fehler bei lambda

  • Klammern um die Parameter vergessen: (lambda a b ...) statt (lambda (a b) ...).

  • Falsche Anzahl Argumente: (tile s1) → Fehler, tile erwartet zwei Eingaben.

  • Parameter außerhalb des Rumpfs benutzen: a und b gibt es nur innerhalb des lambda.

  • (define (tile a b) ...) – diese Kurzschreibweise aus anderem Racket gibt es in der Lehrsprache nicht.

1.6 Information und Daten

Information ist etwas über die echte Welt („In Tübingen sind es 23 Grad“). Daten sind die vereinfachte Form, mit der ein Programm rechnet (die Zahl 23). Die Zuordnung zwischen beiden heißt Repräsentation.

Das Problem: Dieselbe Zahl kann ganz Verschiedenes bedeuten – 23 Haare, 23 Grad, 23 Quadratmeter, Rückennummer 23. Das Programm weiß das nicht. Deshalb schreibt man mit einem Kommentar dazu, welche Information gemeint ist:

(define bruce-willis 23)          ; Anzahl der Haare
(define temperatur-tübingen 23)   ; 23 °C in Tübingen

1.7 Programme systematisch konstruieren

Ab hier geht es nicht mehr darum, wie DrRacket rechnet, sondern wie man ein Programm Schritt für Schritt baut. In der Lehrsprache heißt „ein Programm schreiben“ fast immer: eine Funktion schreiben.

Das Beispiel: Stromtarife. Ein Stromanbieter verlangt eine monatliche Grundgebühr plus einen Preis pro Kilowattstunde (kWh):

TarifGrundgebühr pro MonatPreis pro kWh
Billig-Strom4,90 €0,19 €
Watt für wenig8,20 €0,16 €

Die Rechnung für Billig-Strom ist also: Grundgebühr + Preis × Verbrauch.

(define billig-strom
  (lambda (kWh)
    (+ 4.90 (* 0.19 kWh))))
AufrufRechnungErgebnis
(billig-strom 10)4,90 + 0,19 · 106.8
(billig-strom 20)4,90 + 0,19 · 208.7
(billig-strom 30)4,90 + 0,19 · 3010.6

Zwei neue Begriffe: Das Gerüst ist die „leere Hülle“ einer Funktion – define, lambda, Parameter, und ... statt Rumpf. Der Rumpf ist der Teil, der wirklich rechnet ((+ 4.90 (* 0.19 kWh))). Das Gerüst schreibt man immer zuerst, auch wenn man den Rumpf noch nicht weiß.

Kommazahlen: In der Lehrsprache werden Zahlen wie 4.90 und 0.19 exakt gespeichert (als Bruch), deshalb kommt genau 6.8 heraus und nicht 6.800000001.

1.8 Kurzbeschreibung

Jede Funktion bekommt als Erstes einen Kommentar mit einem Satz, was sie tut:

; monatlichen Rechnungsbetrag für Tarif Billig-Strom berechnen

Die Kurzbeschreibung zwingt dich, die Aufgabe zu verstehen, bevor du programmierst, und sie hilft später allen, die das Programm lesen.

1.9 Signatur

Die Signatur sagt, welche Sorte von Werten eine Funktion bekommt und liefert. Man schreibt sie mit : vor die Definition:

(: billig-strom (natural -> rational))
;  Name          Eingabe  -> Ausgabe

Gelesen: „billig-strom bekommt eine natürliche Zahl und liefert eine rationale Zahl.“ Der Pfeil -> trennt die Eingaben (links) von der Ausgabe (rechts). Bei mehreren Eingaben stehen sie nebeneinander: (: f (number string -> boolean)).

Die eingebauten Signaturen für Zahlen bilden einen „Turm“ – jede Sorte ist in der nächsten enthalten:

SignaturWerteBeispiele
naturalnatürliche Zahlen 0, 1, 2, …0, 42
integerganze Zahlen-3, 0, 17
rationalBrüche (auch Kommazahlen)1/3, 4.9
realreelle Zahlen3.14159, (sqrt 2)
numberalle Zahlenalles oben

Also: natural ⊂ integer ⊂ rational ⊂ real ⊂ number. Dazu kommen string (Text), boolean (Wahrheitswerte, ab Kapitel 2), image (Bilder aus image.rkt) und any (alles).

Was bringt das? DrRacket prüft die Signatur bei jedem Aufruf. Ruft man (billig-strom "30") auf, erscheint eine Signaturverletzung: DrRacket zeigt den falschen Wert ("30") und die erwartete Signatur (natural) und verlinkt die Stellen im Programm. So findet man Fehler dort, wo sie entstehen.

Faustregel: Die Signatur so genau wie möglich wählen. (number -> number) wäre für billig-strom nicht falsch, sagt aber weniger als (natural -> rational).

1.10 Tests

Tests schreibst du vor der Funktion. Damit legst du fest, was richtig ist, bevor du anfängst – und DrRacket prüft es bei jedem Start automatisch.

(check-expect (billig-strom 0) 4.9)     ; einfachster Fall: nur Grundgebühr
(check-expect (billig-strom 10) 6.8)
(check-expect (billig-strom 20) 8.7)
(check-expect (billig-strom 30) 10.6)

(check-expect Ausdruck erwartet) rechnet den Ausdruck aus und vergleicht mit dem erwarteten Wert.

Was DrRacket meldet

SituationMeldung
alle Tests stimmen„Alle 4 Tests bestanden!“
ein Test schlägt fehl (z. B. 5.90 statt 4.90 getippt)„Check-Fehler: Der tatsächliche Wert 7.8 ist nicht der erwartete Wert 6.8.“

Gute Tests

  • Einfache Funktionen brauchen etwa drei Tests, kompliziertere mehr.

  • Fang mit dem einfachsten Fall an (hier: Verbrauch 0).

  • Abdeckung: Jeder Teil des Codes soll von mindestens einem Test ausgeführt werden. Farbig hinterlegter Code = es fehlen Tests.

  • Auch Bilder kann man testen: Bild in der REPL erzeugen, prüfen, ob es stimmt, dann in einen check-expect kopieren.

  • Extra: Für Kommazahlen mit Rundungsfehlern gibt es (check-within ausdruck erwartet toleranz), z. B. (check-within (sqrt 2) 1.414 0.001).

1.11 Konstruktionsanleitungen

Das Herzstück des Buchs: Jede Funktion wird nach demselben Ablauf gebaut.

  1. Kurzbeschreibung – ein Satz als Kommentar.

  2. Datenanalyse – welche Daten kommen vor? (wird ab Kapitel 2 wichtig)

  3. Signatur-Deklaration – Name, Eingaben, Ausgabe, so genau wie möglich.

  4. Tests – einfache, aber interessante Beispiele mit check-expect; sie sollen den ganzen Code abdecken.

  5. Gerüst – aus der Signatur: (define name (lambda (p1 p2 …) ...)), ein Parameter pro Eingabe.

  6. Schablone – ergibt sich aus der Datenanalyse (ab Kapitel 2).

  7. Rumpf – die ... durch den eigentlichen Code ersetzen.

Ganz durchgespielt: Tarif „Watt für wenig“

; 1. Kurzbeschreibung
; monatlichen Rechnungsbetrag für Tarif Watt für wenig berechnen

; 3. Signatur
(: watt-für-wenig (natural -> rational))

; 4. Tests
(check-expect (watt-für-wenig 0) 8.2)
(check-expect (watt-für-wenig 10) 9.8)
(check-expect (watt-für-wenig 20) 11.4)
(check-expect (watt-für-wenig 30) 13.0)

; 5. Gerüst                      ; 7. Rumpf eingesetzt
; (define watt-für-wenig
;   (lambda (kWh)
;     ...))
(define watt-für-wenig
  (lambda (kWh)
    (+ 8.20 (* 0.16 kWh))))

1.12 Die Macht der Abstraktion

billig-strom und watt-für-wenig sind fast gleich – nur Grundgebühr und Preis pro kWh unterscheiden sich. Doppelter Code ist gefährlich: Findet man einen Fehler, muss man ihn an mehreren Stellen korrigieren. Deshalb abstrahiert man:

  1. Eine der Funktionen kopieren und umbenennen.

  2. Die Stellen, die sich unterscheiden, durch neue Namen ersetzen (grundgebühr, pro-kWh).

  3. Diese Namen als Parameter ins lambda aufnehmen.

  4. Signatur schreiben.

  5. Tests anpassen.

  6. Die alten Funktionen durch Aufrufe der neuen ersetzen.

; Rechnungsbetrag für einen beliebigen Stromtarif berechnen
(: stromtarif-rechnungsbetrag (rational rational natural -> rational))

(check-expect (stromtarif-rechnungsbetrag 4.90 0.19 10) 6.8)
(check-expect (stromtarif-rechnungsbetrag 8.20 0.16 10) 9.8)

(define stromtarif-rechnungsbetrag
  (lambda (grundgebühr pro-kWh kWh)
    (+ grundgebühr (* pro-kWh kWh))))

; Die einzelnen Tarife nutzen jetzt die allgemeine Funktion:
(define billig-strom
  (lambda (kWh)
    (stromtarif-rechnungsbetrag 4.90 0.19 kWh)))

(define watt-für-wenig
  (lambda (kWh)
    (stromtarif-rechnungsbetrag 8.20 0.16 kWh)))

Das ist dieselbe Idee wie bei tile: Was sich ändert, wird zum Parameter.

2.1 Boolesche Werte

Es gibt genau zwei Wahrheitswerte (auch boolesche Werte, nach dem Mathematiker George Boole): #t für wahr (true) und #f für falsch (false). Sie sind Literale wie Zahlen. Ein Ausdruck, der einen Wahrheitswert liefert, heißt Bedingung. Liefert er #t, sagt man: Die Bedingung gilt.

Vergleiche

AusdruckBedeutungErgebnis

or ist ein inklusives Oder: Auch wenn beide Operanden #t sind, ist das Ergebnis #t. Das umgangssprachliche „entweder … oder“ (exklusives Oder) gibt es nicht eingebaut – eine typische Übung.

Die Signatur für Wahrheitswerte heißt boolean. Namenskonvention: Funktionen, die einen Wahrheitswert liefern (Prädikate), enden mit ?, z. B. string=? oder später cute?.

2.2 Verzweigungen mit cond

Eine Fallunterscheidung liegt vor, wenn ein Wert zu einer von mehreren Kategorien gehört. Dafür gibt es cond. Es besteht aus Zweigen; jeder Zweig ist ein Paar aus Bedingung und Ergebnis:

(cond
  (Bedingung-1 Ergebnis-1)
  (Bedingung-2 Ergebnis-2)
  ...)

Beispiel: Zahl als Wort

; Zahl zwischen 0 und 3 als englisches Wort ausgeben
(: say-number ((integer-from-to 0 3) -> string))

(check-expect (say-number 0) "zero")
(check-expect (say-number 2) "two")

(define say-number
  (lambda (n)
    (cond
      ((= n 0) "zero")
      ((= n 1) "one")
      ((= n 2) "two")
      ((= n 3) "three"))))

(integer-from-to 0 3) ist eine Signatur für „ganze Zahl von 0 bis 3“ – genauer als natural. Ruft man (say-number 7) auf, meldet DrRacket sofort eine Signaturverletzung.

So wertet DrRacket (say-number 2) aus

  1. n wird durch 2 ersetzt.

  2. Erster Zweig: (= 2 0) → #f, also weiter.

  3. Zweiter Zweig: (= 2 1) → #f, also weiter.

  4. Dritter Zweig: (= 2 2) → #t – Treffer! Ergebnis: "two". Die restlichen Zweige werden nicht mehr angeschaut.

Im Stepper sieht man genau diese Reihenfolge.

2.3 Abdeckung

Ein Ausdruck ist abgedeckt, wenn mindestens ein Test ihn ausführt. Bei cond bedeutet das: Jeder Zweig braucht mindestens einen Test. DrRacket hinterlegt nicht ausgeführte Zweige nach dem Start farbig. Bei say-number oben fehlen also noch Tests für 1 und 3.

2.4 Aufzählungen

Eine Aufzählung ist eine Datensorte mit einer festen, kleinen Menge von Werten. Man beschreibt sie zuerst mit einer Datendefinition (Kommentar) und dann mit einer Signatur-Definition:

; Ein Haustier ist eins der folgenden:
; - Katze
; - Hund
; - Schlange
(define pet
  (signature (enum "Katze" "Hund" "Schlange")))

  • signature erzeugt eine neue Signatur.

  • enum zählt die erlaubten Werte auf (darf nur innerhalb von signature stehen).

  • Danach kann pet wie natural oder string in Signaturen benutzt werden.

; Ist ein Haustier niedlich?
(: cute? (pet -> boolean))

(check-expect (cute? "Katze") #t)
(check-expect (cute? "Hund") #t)
(check-expect (cute? "Schlange") #f)

(define cute?
  (lambda (p)
    (cond
      ((string=? p "Katze") #t)
      ((string=? p "Hund") #t)
      ((string=? p "Schlange") #f))))

Wichtig: Zeichenketten vergleicht man mit string=?, nicht mit =. Mit = meldet DrRacket: „=: Zahl als erstes Argument erwartet, "Katze" bekommen“.

2.5 Zahlenbereiche

Oft teilt man Zahlen in Bereiche (Intervalle) ein. Das Buch nimmt dazu Wasser, das erhitzt wird: Es wird wärmer, aber nie heißer als 100 °C (dann kocht es).

; Temperatur von Wasser nach Zuführen von Wärme berechnen (ohne Eis)
(: heat-water-1 (real real -> real))

(check-expect (heat-water-1 20 30) 50)
(check-expect (heat-water-1 99 1) 100)    ; Grenzfall: genau 100
(check-expect (heat-water-1 99 2) 100)    ; Grenzfall: knapp drüber
(check-expect (heat-water-1 50 200) 100)

(define heat-water-1
  (lambda (temp heat)
    (cond
      ((<= (+ temp heat) 100) (+ temp heat))
      ((> (+ temp heat) 100) 100))))

Grenzfälle testen! Bei Zahlenbereichen passieren die meisten Fehler genau an den Grenzen (hier: 100). Teste den Wert direkt an der Grenze und einen knapp daneben.

else: Der letzte Zweig darf statt einer Bedingung else haben. Er greift, wenn alle anderen Bedingungen #f waren:

(cond
  ((<= (+ temp heat) 100) (+ temp heat))
  (else 100))

Mit Eis und Schmelzen: Unter 0 °C ist Wasser Eis. Um Eis von 0 °C zu schmelzen, braucht man so viel Wärme wie für 80 Grad Erwärmung – solange bleibt die Temperatur bei 0. Mit vielen verschachtelten Fällen wird das unübersichtlich und fehleranfällig. Eine elegante Lösung: Man rechnet alles in eine „Wärmemenge“ um und wieder zurück.

; Wärmemenge in Temperatur umrechnen
; (Eis bis 0, dann 80 Einheiten Schmelzen bei 0 °C, dann Wasser bis 100)
(: heat->temperature (real -> real))
(define heat->temperature
  (lambda (heat)
    (cond
      ((<= heat 0) heat)                           ; Eis
      ((and (< 0 heat) (<= heat 80)) 0)            ; schmelzendes Eis
      ((and (< 80 heat) (<= heat 180)) (- heat 80)); flüssiges Wasser
      ((< 180 heat) 100))))                        ; kochendes Wasser

; Temperatur in Wärmemenge umrechnen (0 °C zählt als Eis)
(: temperature->heat (real -> real))
(define temperature->heat
  (lambda (temp)
    (if (<= temp 0)
        temp
        (+ temp 80))))

; Temperatur nach Zuführen von Wärme, mit Eis und Schmelzen
(: heat-water-2 (real real -> real))

(check-expect (heat-water-2 -10 5) -5)     ; bleibt Eis
(check-expect (heat-water-2 -10 50) 0)     ; schmilzt gerade
(check-expect (heat-water-2 -10 100) 10)   ; geschmolzen, 10 °C
(check-expect (heat-water-2 -1 191) 100)   ; kocht

(define heat-water-2
  (lambda (temp heat)
    (heat->temperature (+ (temperature->heat temp) heat))))

Rechenweg für (heat-water-2 -10 100): (temperature->heat -10) → -10; plus 100 → 90; (heat->temperature 90) → 90 liegt zwischen 80 und 180 → (- 90 80) → 10.

2.6 Datenanalyse und Schablonen

Jetzt kommen die Schritte 2 und 6 der Konstruktionsanleitung dazu:

  • Datenanalyse: Suche in der Aufgabe die wichtigen Größen (meist Substantive) und schreibe für jede eine Datendefinition als Kommentar. Formulierungen wie „ist eins der folgenden“ oder „liegt zwischen … und …“ deuten auf eine Fallunterscheidung hin.

  • Schablone: Aus der Datenanalyse ergibt sich ein unfertiges Programm. Für Fallunterscheidungen:

(define f
  (lambda (a)
    (cond
      (... ...)
      ...
      (... ...))))

Regel: So viele Zweige wie Fälle in der Datendefinition. Erst die Bedingungen ausfüllen, dann die Ergebnisse.

2.7 Exkurs: Verzweigungen in der Mathematik

In der Mathematik schreibt man Fallunterscheidungen mit einer geschweiften Klammer, z. B. |x| = x für x ≥ 0 und −x für x < 0. Dort müssen alle Bedingungen vollständig dastehen, weil es keine „Reihenfolge“ gibt. In Racket werden die Zweige von oben nach unten geprüft – ein späterer Zweig kann sich darauf verlassen, dass die früheren nicht gegriffen haben. Das ist bequem, aber man muss die Reihenfolge im Blick behalten.

2.8 Binäre Verzweigungen mit if

Gibt es genau zwei Fälle, abhängig von einer Bedingung, ist if kürzer:

(if Bedingung Konsequente Alternative)

  • Konsequente: Ergebnis, wenn die Bedingung #t ist.

  • Alternative: Ergebnis, wenn die Bedingung #f ist.

; Haustier gegen ein niedliches tauschen, falls nötig
(: exchange-for-cute (pet -> pet))

(check-expect (exchange-for-cute "Hund") "Hund")
(check-expect (exchange-for-cute "Schlange") "Katze")

(define exchange-for-cute
  (lambda (p)
    (if (cute? p)
        p
        "Katze")))

Schablone für boolesche Fallunterscheidungen: Wenn die Unterscheidung an einem Wahrheitswert hängt, if verwenden.

2.9 Syntaktischer Zucker

cond, and und or sind eigentlich nur bequeme Abkürzungen für verschachtelte ifs – man nennt das syntaktischen Zucker oder abgeleitete Formen:

Kurzformist dasselbe wie
(and a b c)(if a (if b c #f) #f)
(or a b c)(if a #t (if b #t c))
(cond (b1 e1) (b2 e2) (else e3))(if b1 e1 (if b2 e2 e3))

Daraus folgt auch: and hört beim ersten #f auf, or beim ersten #t – der Rest wird gar nicht ausgewertet. Nützliche Vereinfachungen: (if b #t #f) ist einfach b, und (if b #t a) ist (or b a).

2.10 Unsinnige Daten abfangen

Manche Eingaben passen zur Signatur, ergeben aber keinen Sinn – z. B. Wasser mit 150 °C. Statt ein scheinbar richtiges, aber falsches Ergebnis zu liefern, bricht man mit violation ab:

(define heat-water-checked
  (lambda (temp heat)
    (cond
      ((> temp 100) (violation "Anfangstemperatur über 100 °C"))
      (else (heat-water-2 temp heat)))))

(check-error (heat-water-checked 150 0))   ; Test: hier MUSS ein Fehler kommen

  • (violation "Text") beendet das Programm mit dieser Fehlermeldung.

  • (check-error Ausdruck) ist ein Test, der besteht, wenn der Ausdruck einen Fehler auslöst.

Trifft bei cond kein Zweig zu und gibt es kein else, meldet die Lehrsprache: „cond: alle Bedingungen ergaben #f“.

3.1 Computer konfigurieren

Ein Computer besteht aus Prozessor (Name), Arbeitsspeicher (RAM in GB) und Festplatte (in GB). Erst die Datendefinition, dann die Record-Definition:

; Ein Computer besteht aus:
; - Prozessor
; - Arbeitsspeicher (RAM) in Gigabyte
; - Festplattenkapazität in Gigabyte
(define-record computer
  make-computer
  (computer-processor  string)
  (computer-ram        natural)
  (computer-hard-drive natural))

Aufbau von define-record (der Reihe nach):

  1. computer – Name des Record-Typs; gleichzeitig die Signatur für solche Werte.

  2. make-computer – der Konstruktor: baut einen neuen Computer.

  3. Für jedes Feld ein Paar (Selektor Signatur): computer-ram holt den RAM-Wert heraus und muss eine natural sein.

Optional kann zwischen Konstruktor und Feldern noch ein Prädikat stehen (z. B. computer?) – das wird in Kapitel 4 wichtig.

Was dabei automatisch entsteht (diese Signaturen muss man nicht hinschreiben, sie ergeben sich aus der Definition):

(: make-computer (string natural natural -> computer))
(: computer-processor (computer -> string))
(: computer-ram (computer -> natural))
(: computer-hard-drive (computer -> natural))

Benutzen in der REPL

(define gamer (make-computer "Cell" 4 1000))
gamer                  ; => #<record:computer "Cell" 4 1000>
(computer-ram gamer)   ; => 4
(computer-processor gamer) ; => "Cell"

Feld und Komponente: „RAM“ ist ein Feld (jeder Computer hat es); 4 ist die Komponente dieses einen Computers.

Funktion mit Record als Eingabe: Gesamtspeicher

; Gesamtspeicher (RAM + Festplatte) berechnen
(: total-memory (computer -> natural))

(define workstation (make-computer "Xeon" 2 500))
(check-expect (total-memory workstation) 502)
(check-expect (total-memory gamer) 1004)

(define total-memory
  (lambda (c)
    (+ (computer-ram c)
       (computer-hard-drive c))))

Funktion mit Record als Ausgabe: Standardkonfigurationen

(define model

3.2 Zusammengesetzte Daten selbst konstruieren: die Uhrzeit

(define hour   (signature (integer-from-to 0 23)))
(define minute (signature (integer-from-to 0 59)))

; Eine Uhrzeit besteht aus:

(define-record wallclock-time

3.3 Konstruktionsanleitungen für zusammengesetzte Daten

Datenanalyse: Zusammengesetzte Daten erkennt man an Formulierungen wie „besteht aus“, „hat“ oder „ist charakterisiert durch“. Die Datendefinition listet die Teile auf.

Record-Definition: Typname T, Feldnamen f1 … fn mit Signaturen. Die Namen folgen der Konvention make-T (Konstruktor), T? (Prädikat), T-f1 … T-fn (Selektoren).

Schablone, wenn ein Record die Eingabe ist:

(define f
  (lambda (r)
    ... (T-f1 r) ... (T-f2 r) ...))

Für jedes Feld einen Selektor-Aufruf hinschreiben, dann daraus den Rumpf bauen und nicht benutzte Selektoren löschen. (Ein ungenutzter Selektor kann ein Hinweis auf einen Denkfehler sein.)

Schablone, wenn ein Record die Ausgabe ist: ein Konstruktor-Aufruf mit einer Lücke pro Feld:

(make-wallclock-time ... ...)

3.4 Ein- und Ausgabe zusammengesetzter Daten: Gürteltiere

Ein Gürteltier (englisch armadillo, kurz dillo) hat ein Gewicht (in Gramm) und ist lebendig oder tot:

; Ein Gürteltier hat folgende Eigenschaften:
; - Gewicht (in g)
; - lebendig oder tot
(define-record dillo
  make-dillo
  (dillo-weight natural)
  (dillo-alive? boolean))

(define dillo1 (make-dillo 55000 #t))   ; 55 kg, lebendig
(define dillo2 (make-dillo 58000 #f))   ; 58 kg, tot

Füttern – Record rein, Record raus. Nur lebendige Tiere nehmen 500 g zu:

(: feed-dillo (dillo -> dillo))

(check-expect (feed-dillo dillo1) (make-dillo 55500 #t))
(check-expect (feed-dillo dillo2) dillo2)

(define feed-dillo
  (lambda (dillo)
    (if (dillo-alive? dillo)
        (make-dillo (+ (dillo-weight dillo) 500) #t)
        dillo)))

Hier kommen drei Schablonen zusammen: Selektoren (Eingabe), Konstruktor (Ausgabe) und if (Fallunterscheidung nach dillo-alive?).

Überfahren – das Gewicht bleibt, das Tier ist danach immer tot:

(: run-over-dillo (dillo -> dillo))

(check-expect (run-over-dillo dillo1) (make-dillo 55000 #f))
(check-expect (run-over-dillo dillo2) dillo2)

(define run-over-dillo
  (lambda (dillo)
    (make-dillo (dillo-weight dillo) #f)))

Der Selektor dillo-alive? wurde aus der Schablone gelöscht – er wird nicht gebraucht, weil das Ergebnis in jedem Fall tot ist.

Wichtig: Ein Record wird nie „verändert“. feed-dillo baut ein neues Gürteltier; dillo1 bleibt, wie es war.

3.5 Alternativen bei den Konstruktionsanleitungen

Oft gibt es mehrere richtige Lösungen. Bei feed-dillo kann die Verzweigung auch innerhalb des Konstruktors stehen:

; Variante B: Verzweigung im Konstruktor
(define feed-dillo
  (lambda (dillo)
    (make-dillo (if (dillo-alive? dillo)
                    (+ (dillo-weight dillo) 500)
                    (dillo-weight dillo))
                (dillo-alive? dillo))))

Mit einer Gleichung kann man Programme vereinfachen: Baut man ein Gürteltier aus genau den Teilen eines anderen, kommt dasselbe heraus:

(make-dillo (dillo-weight d) (dillo-alive? d)) = d

Damit lässt sich Variante B wieder in Variante A (aus 3.4) umformen. Beide sind richtig; A erzeugt für tote Tiere keinen neuen Wert, B ist kürzer.

4.3 Die Lebensmittelampel

Auf Lebensmitteln wird der Zuckergehalt oft als Ampel angegeben. Die Angabe kann aber in drei Formen vorliegen: als Zahl (Gramm Zucker), als Aufschlüsselung (Fruktose + Glukose) oder schon als Ampelfarbe. Das sind gemischte Daten aus einer Zahl, einem Record und einer Aufzählung:

; Eine Ampelfarbe ist eins der folgenden: "red", "yellow", "green"
(define traffic-light (signature (enum "red" "yellow" "green")))

; Zuckeranteile bestehen aus Fruktose und Glukose (in g)
(define-record sugars
  make-sugars
  sugars?
  (sugars-fructose-g rational)
  (sugars-glucose-g rational))

; - Gramm Zucker (Zahl)
; - Zuckeranteile
; - Ampelfarbe
(define sugar-content (signature (mixed rational sugars traffic-light)))

; Gramm Zucker (pro 100 g) in Ampelfarbe umrechnen
; bis 5 g grün, bis 22,5 g gelb, darüber rot
(: sugar-weight->traffic-light (rational -> traffic-light))

  (lambda (g)

4.4 Fehler repräsentieren

Manche Fragen haben keine sinnvolle Antwort. Die Steigung einer Geraden durch zwei Punkte ist (y2 − y1) / (x2 − x1) – aber für eine senkrechte Gerade (x1 = x2) teilt man durch 0. DrRacket meldet dann „/: durch 0 geteilt“ und das Programm stürzt ab, ohne die eigentliche Ursache zu nennen.

Besser: einen eigenen Wert für „keine Steigung“ zurückgeben. Dafür eignet sich ein Record ohne Felder („entarteter“ Record) – davon gibt es genau einen Wert:

; Es gibt keine Steigung
(define-record no-slope
  make-no-slope
  no-slope?)

; Steigung der Geraden durch (x1, y1) und (x2, y2) berechnen
(: slope (real real real real -> (mixed real no-slope)))

(check-expect (slope 0 0 2 4) 2)
(check-expect (no-slope? (slope 0 0 0 1)) #t)

(define slope
  (lambda (x1 y1 x2 y2)
    (if (= (- x2 x1) 0)
        (make-no-slope)
        (/ (- y2 y1) (- x2 x1)))))

Die Signatur (mixed real no-slope) sagt jetzt ehrlich: „Es kommt eine Zahl oder keine Steigung heraus.“ Wer slope benutzt, muss beide Fälle behandeln.

Kapitel 5: Programmieren mit Selbstbezügen und Kombinatoren

Funktionen, die aus kleinen Daten größere derselben Art bauen, heißen Kombinatoren.

5.1 Flüsse abbilden

Ein Fluss ist entweder ein Bach (eine Quelle) oder ein Zusammenfluss zweier Flüsse an einem Ort. Der Zusammenfluss enthält also wieder Flüsse – das ist der Selbstbezug.

; Ein Fluss ist eins der folgenden:
; - ein Bach
; - ein Zusammenfluss
(define river (signature (mixed creek confluence)))

; Ein Bach hat einen Ursprung (Ort der Quelle)
(define-record creek
  make-creek
  creek?
  (creek-origin string))

; Ein Zusammenfluss hat einen Ort, einen Hauptfluss und einen Nebenfluss
(define-record confluence
  make-confluence
  confluence?
  (confluence-location string)
  (confluence-main-stem river)      ; Selbstbezug!
  (confluence-tributary river))     ; Selbstbezug!

Beispieldaten: der obere Neckar

(define eschach   (make-creek "Heimliswald"))
(define prim      (make-creek "Dreifaltigkeitsberg"))
(define neckar-1  (make-confluence "Rottweil" eschach prim))
(define schlichem (make-creek "Tieringen"))
(define neckar-2  (make-confluence "Epfendorf" neckar-1 schlichem))

Als Baum gezeichnet:

;              Epfendorf (neckar-2)
;              /                \
;      Rottweil (neckar-1)    Tieringen (schlichem)
;       /          \
;  Heimliswald   Dreifaltigkeitsberg
;  (eschach)     (prim)

Frage: Fließt Wasser von einem bestimmten Ort in diesen Fluss?

; Fließt Wasser von location in river?
(: flows-from? (string river -> boolean))

(check-expect (flows-from? "Heimliswald" neckar-2) #t)
(check-expect (flows-from? "Rottweil" neckar-2) #t)
(check-expect (flows-from? "Berlin" neckar-2) #f)

(define flows-from?
  (lambda (location river)
    (cond
      ((creek? river)
       (string=? (creek-origin river) location))
      ((confluence? river)
       (or (string=? (confluence-location river) location)
           (flows-from? location (confluence-main-stem river))     ; rekursiv
           (flows-from? location (confluence-tributary river)))))))  ; rekursiv

Schablone bei Selbstbezug: Zuerst die normale Schablone (hier: gemischte Daten → cond mit Prädikaten; zusammengesetzte Daten → Selektoren). Dann: An jeder Stelle, wo die Datendefinition einen Selbstbezug hat, einen rekursiven Aufruf hinschreiben.

So wertet DrRacket (flows-from? "Heimliswald" neckar-1) aus

  1. neckar-1 ist ein Zusammenfluss → zweiter Zweig.

  2. (string=? "Rottweil" "Heimliswald") → #f, also weiter im or.

  3. Rekursiver Aufruf mit dem Hauptfluss eschach: ein Bach → (string=? "Heimliswald" "Heimliswald") → #t.

  4. or hat ein #t gefunden → Ergebnis #t. Der Nebenfluss wird gar nicht mehr angeschaut.

Warum hört das auf? Jeder rekursive Aufruf bekommt einen kleineren Fluss. Irgendwann landet man immer bei einem Bach – dem Basisfall ohne Rekursion.

Vereinfachungen: (if b #t a) ist dasselbe wie (or b a), und (if b #t #f) ist einfach b. Deshalb steht oben ein or statt verschachtelter ifs.

5.2 Bilder modellieren

Schon in Kapitel 1 hattest du Selbstbezug, ohne es zu merken: beside und above nehmen Bilder und liefern ein Bild.

(: beside (image image -> image))
(: above  (image image -> image))
(: make-confluence (string river river -> river))

Alle drei haben dasselbe Muster: Sie bauen aus kleineren Dingen ein größeres Ding derselben Sorte. Solche Funktionen heißen Kombinatoren. Weil das Ergebnis wieder dieselbe Sorte hat, kann man sie beliebig verschachteln – deshalb funktioniert (tile (tile s1 p1) c1). Kombinatoren stecken oft versteckt in Aufgaben; es lohnt sich, gezielt danach zu suchen (Mantra „Kombinatoren“).

6.2 Listen mit anderen Elementen

Listen von Zahlen reichen nicht – man will auch Listen von Strings, Tieren, Bildern. Statt für jede Sorte eine eigene Liste zu definieren, macht man die Elementsorte zum Parameter:

  • list-of ist ein Signatur-Konstruktor: (list-of number), (list-of string), (list-of dillo).

  • Eine Signaturvariable beginnt mit % und steht für eine beliebige Signatur: (list-of %element) = „Liste mit irgendwelchen Elementen“.

  • Funktionen, deren Signatur Signaturvariablen enthält, heißen polymorph (vielgestaltig).

Die eingebauten Grundfunktionen haben diese Signaturen:

(: cons  (%element (list-of %element) -> (list-of %element)))
(: first ((list-of %element) -> %element))
(: rest  ((list-of %element) -> (list-of %element)))

6.3 Konstruktionsanleitung für Listen

Die Schablone verbindet drei bekannte Schablonen: gemischte Daten (cond mit empty?/cons?), zusammengesetzte Daten (first, rest) und Selbstbezug (rekursiver Aufruf auf rest):

(define f
  (lambda (list)
    (cond
      ((empty? list) ...)
      ((cons? list)
       ... (first list)
       ... (f (rest list)) ...))))

Merksatz: Im empty-Fall steht das Ergebnis für die leere Liste (oft das neutrale Element). Im cons-Fall nimmst du an, dass der rekursive Aufruf für den Rest schon stimmt, und überlegst nur, wie du (first list) dazunimmst.

6.7 Minimum einer Liste und lokale Variablen

Das Minimum einer leeren Liste gibt es nicht. Wie in Kapitel 4 nimmt man einen eigenen Wert dafür:

(define-record no-result make-no-result no-result?)

; Kleinstes Element einer Liste finden
(: list-min ((list-of real) -> (mixed real no-result)))

(check-expect (no-result? (list-min empty)) #t)
(check-expect (list-min (list 4 2 9)) 2)

(define list-min
  (lambda (list)
    (cond
      ((empty? list) (make-no-result))
      ((cons? list)
       (define rest-min (list-min (rest list)))     ; lokale Variable
       (if (no-result? rest-min)
           (first list)
           (min (first list) rest-min))))))

Lokale Variable: Ein define am Anfang eines lambda-Rumpfs oder eines cond-Zweigs gilt nur dort. Ohne sie müsste man (list-min (rest list)) bis zu dreimal hinschreiben – und DrRacket würde es auch dreimal ausrechnen. Bei langen Listen wird das extrem langsam, weil sich die Arbeit bei jeder Ebene verdreifacht.

6.8 Funktionen auf nichtleeren Listen

Alternative: Man verbietet die leere Liste schon in der Signatur. Dann braucht man kein no-result:

(: list-min-nonempty ((nonempty-list-of real) -> real))

(check-expect (list-min-nonempty (list 7)) 7)
(check-expect (list-min-nonempty (list 4 2 9)) 2)

(define list-min-nonempty
  (lambda (list)
    (cond
      ((empty? (rest list)) (first list))           ; nur noch ein Element
      ((cons? (rest list))
       (min (first list) (list-min-nonempty (rest list)))))))

Die Schablone unterscheidet hier nicht (empty? list), sondern (empty? (rest list)): Der Basisfall ist die Liste mit einem Element.

7.3 Andersrum zählen

Mit der Schablone bekommt man Listen, die absteigend zählen. Eine aufsteigende Liste von from bis to braucht einen Trick. Man löst zuerst ein Hilfsproblem: „Gib count Zahlen ab from aus“ – hier ist count die natürliche Zahl, über die die Rekursion läuft:

; count aufeinanderfolgende ganze Zahlen ab from
(: count-from (integer natural -> (list-of integer)))

(check-expect (count-from 3 5) (list 3 4 5 6 7))

(define count-from
  (lambda (from count)
    (cond
      ((zero? count) empty)
      ((positive? count)
       (cons from (count-from (+ from 1) (- count 1)))))))

; alle ganzen Zahlen von from bis to
(: between (integer integer -> (list-of integer)))

(check-expect (between 3 7) (list 3 4 5 6 7))
(check-expect (between -2 1) (list -2 -1 0 1))

(define between
  (lambda (from to)
    (count-from from (+ (- to from) 1))))

Von 3 bis 7 sind es 7 − 3 + 1 = 5 Zahlen. Das „+ 1“ wird gern vergessen – ein klassischer Um-eins-daneben-Fehler (englisch off by one).

7.4 Exkurs: Potenz optimieren

power braucht für b¹⁰⁰⁰ tausend Multiplikationen. Schneller geht es mit einem Trick: b¹⁰⁰⁰ = (b⁵⁰⁰)². Man halbiert also den Exponenten und quadriert das Ergebnis. Dafür braucht man eine andere Datendefinition: Eine natürliche Zahl ist 0, gerade (das Doppelte einer Zahl) oder ungerade (das Doppelte plus 1).

(: power2 (number natural -> number))

(check-expect (power2 2 10) 1024)
(check-expect (power2 3 5) 243)

(define power2
  (lambda (base exponent)
    (cond
      ((zero? exponent) 1)
      ((even? exponent)
       (define half (power2 base (quotient exponent 2)))
       (* half half))
      ((odd? exponent)
       (define half (power2 base (quotient (- exponent 1) 2)))
       (* half half base)))))

Die lokale Definition half sorgt dafür, dass das halbe Ergebnis nur einmal berechnet wird. Für b¹⁰⁰⁰ braucht power2 nur etwa 15 Multiplikationen statt 1000.

8.2 Aussagen über natürliche Zahlen

Viele Formeln gelten „für alle n“, zum Beispiel die Gauß’sche Summenformel:

0+1+2+⋯+n=n(n+1)20 + 1 + 2 + \dots + n = \frac{n(n+1)}{2}0+1+2+⋯+n=2n(n+1)​

Man kann sie für n = 0, 1, 2, 3 nachrechnen – aber nicht für alle unendlich vielen n. Dafür gibt es die vollständige Induktion: Man zeigt, dass die Aussage für 0 gilt und dass sie „von jedem n auf n + 1 übergeht“. Dann gilt sie wie bei einer Kette umfallender Dominosteine für alle n.

8.3 Induktive Beweise führen

Das Rezept

  1. Behauptung als „Für alle n ∈ ℕ gilt …“ aufschreiben.

  2. Induktionsanfang: die Behauptung für n = 0 zeigen.

  3. Induktionsvoraussetzung: annehmen, dass die Behauptung für ein bestimmtes n gilt.

  4. Induktionsschluss: zeigen, dass sie dann auch für n + 1 gilt – und dabei die Voraussetzung benutzen.

Durchgerechnet: Gauß’sche Summenformel

  • Behauptung: Für alle n gilt 0 + 1 + … + n = n(n+1)/2.

  • Induktionsanfang (n = 0): Links steht 0, rechts 0 · 1 / 2 = 0. ✓

  • Induktionsvoraussetzung: Für ein n gilt 0 + 1 + … + n = n(n+1)/2.

  • Induktionsschluss (n → n + 1):

0+1+⋯+n⏟=n(n+1)2 (Voraussetzung)+(n+1)=n(n+1)2+2(n+1)2=(n+1)(n+2)2\underbrace{0 + 1 + \dots + n}_{= \frac{n(n+1)}{2} \text{ (Voraussetzung)}} + (n+1) = \frac{n(n+1)}{2} + \frac{2(n+1)}{2} = \frac{(n+1)(n+2)}{2}=2n(n+1)​ (Voraussetzung)0+1+⋯+n​​+(n+1)=2n(n+1)​+22(n+1)​=2(n+1)(n+2)​

Das ist genau die Formel für n + 1. ✓ Damit gilt sie für alle n.

Wichtig: Die Formel finden ist Kreativität (ausprobieren, Muster erkennen). Nur der Beweis folgt einem festen Ablauf.

8.4 Struktur der natürlichen Zahlen

Die natürlichen Zahlen sind induktiv definiert:

  1. Basiselement (Induktionsverankerung): 0 ∈ ℕ.

  2. Regel mit Selbstbezug: Wenn n ∈ ℕ, dann ist auch n + 1 ∈ ℕ.

  3. Induktiver Abschluss: Nichts anderes gehört zu ℕ.

Das ist genau die Datendefinition aus Kapitel 7 – und deshalb hat die Schablone dort zwei Fälle (zero? und positive?). Eine gleichwertige Beschreibung sind die Peano-Axiome (1889), zu denen auch das Induktionsprinzip gehört. Die reellen Zahlen lassen sich nicht so aufbauen – deshalb gibt es für real keine solche Schablone.

8.5 Endliche Folgen

Endliche Folgen (= Listen) über einer Menge M sind ebenfalls induktiv definiert:

  • Die leere Folge ε ist eine Folge.

  • Ist m ∈ M und f eine Folge, dann ist auch m f (m vorne angehängt) eine Folge.

M* bezeichnet die Menge aller endlichen Folgen über M. Die Summe einer Folge definiert man rekursiv:

s(ε)=0s(mf′)=m+s(f′)s(\varepsilon) = 0 \qquad s(m f') = m + s(f')s(ε)=0s(mf′)=m+s(f′)

Beispiel: s(17 23 42 5) = 17 + s(23 42 5) = … = 17 + 23 + 42 + 5 + 0 = 87. Das ist exakt list-sum aus Kapitel 6. Die Rechnung endet immer, weil die Folge bei jedem Schritt kürzer wird.

Folgeninduktion: Um eine Aussage für alle Folgen zu beweisen, zeigt man sie für ε und zeigt: Gilt sie für f, dann auch für m f. Beispiel: Das Aneinanderhängen cat (= concatenate) ist assoziativ: cat(u, cat(v, w)) = cat(cat(u, v), w). Bewiesen wird das durch Induktion über u.

8.7 Strukturelle Rekursion

Eine Funktion über eine induktiv definierte Menge bekommt einen Fall pro Regel; jeder Selbstbezug wird zu einem rekursiven Aufruf. Beispiel: den Wert eines booleschen Ausdrucks ausrechnen. In Racket sieht das so aus (Extra):

; Ein boolescher Ausdruck ist eins der folgenden:
; - #t oder #f
; - (make-und a b), (make-oder a b), (make-nicht a)
(define-record und  make-und  und?  (und-links bool-expr) (und-rechts bool-expr))
(define-record oder make-oder oder? (oder-links bool-expr) (oder-rechts bool-expr))
(define-record nicht make-nicht nicht? (nicht-ausdruck bool-expr))
(define bool-expr (signature (mixed boolean und oder nicht)))

(: auswerten (bool-expr -> boolean))

(check-expect (auswerten (make-und #t (make-nicht #f))) #t)

(define auswerten
  (lambda (e)
    (cond
      ((boolean? e) e)
      ((und? e)   (and (auswerten (und-links e)) (auswerten (und-rechts e))))
      ((oder? e)  (or  (auswerten (oder-links e)) (auswerten (oder-rechts e))))
      ((nicht? e) (not (auswerten (nicht-ausdruck e)))))))

Das ist dieselbe Schablone wie für gemischte Daten mit Selbstbezug (Kapitel 4 und 5).

8.8 Strukturelle Induktion

Beweise über solche Funktionen folgen ebenfalls der Grammatik: ein Beweisfall pro Regel, und für jeden Selbstbezug darf man eine Induktionsvoraussetzung benutzen. Bei e ∧ e gibt es also zwei Voraussetzungen (eine pro Teilausdruck), bei ¬ e eine. Vollständige Induktion (8.3) und Folgeninduktion (8.5) sind Spezialfälle davon.

Beispiel aus dem Buch: Vertauscht man in einem Ausdruck ⊤ mit ⊥ und ∧ mit ∨, kommt genau das Gegenteil heraus (De Morgan). Der Beweis geht Fall für Fall durch: ⊤, ⊥ (Basisfälle), dann ∧, ∨ (je zwei Voraussetzungen) und ¬ (eine Voraussetzung).

9.1 Fußball-Fakten ermitteln

Ein Spiel hat Spieltag, Heimmannschaft, Heimtore, Gastmannschaft und Gasttore. Für einen Sieg gibt es 3 Punkte, für ein Unentschieden 1, für eine Niederlage 0.

(define team (signature string))
(define points (signature (enum 0 1 3)))

(define-record game
  make-game
  game?
  (game-matchday natural)
  (game-home-team team)
  (game-home-goals natural)
  (game-guest-team team)
  (game-guest-goals natural))

(define game1 (make-game 1 "Wolfsburg" 2 "Stuttgart" 0))

Punkte der Heimmannschaft – mit lokalen Definitionen für bessere Lesbarkeit:

(: home-points (game -> points))

(check-expect (home-points game1) 3)

(define home-points
  (lambda (g)
    (define goals1 (game-home-goals g))
    (define goals2 (game-guest-goals g))
    (cond
      ((> goals1 goals2) 3)
      ((< goals1 goals2) 0)
      (else 1))))

guest-points sieht genauso aus – nur mit game-guest-goals und game-home-goals vertauscht. Doppelter Code! Also abstrahieren: Die Selektoren werden zu Parametern.

; Punkte aus Sicht einer Mannschaft berechnen
(: compute-points ((game -> natural) (game -> natural) game -> points))

(define compute-points
  (lambda (get-goals-1 get-goals-2 g)
    (define goals1 (get-goals-1 g))
    (define goals2 (get-goals-2 g))
    (cond
      ((> goals1 goals2) 3)
      ((< goals1 goals2) 0)
      (else 1))))

(compute-points game-home-goals game-guest-goals game1)   ; => 3  (Heim)
(compute-points game-guest-goals game-home-goals game1)   ; => 0  (Gast)

In der Signatur steht (game -> natural) in Klammern: Der Parameter ist selbst eine Funktion.

Funktionsfabrik: Eine Funktion kann auch eine Funktion liefern:

(: make-compute-points ((game -> natural) (game -> natural) -> (game -> points)))

(define make-compute-points
  (lambda (get-goals-1 get-goals-2)
    (lambda (g)
      (compute-points get-goals-1 get-goals-2 g))))

(define home-points  (make-compute-points game-home-goals game-guest-goals))
(define guest-points (make-compute-points game-guest-goals game-home-goals))

Konstruktionsanleitung „Abstraktion“

  1. Eine der ähnlichen Definitionen kopieren und umbenennen.

  2. Die Stellen, an denen sich die Definitionen unterscheiden, durch neue Variablen ersetzen.

  3. Diese Variablen als Parameter ins lambda aufnehmen (rekursive Aufrufe anpassen!).

  4. Signatur schreiben.

  5. Die alten Definitionen durch Aufrufe der neuen ersetzen.

9.2 Higher-Order-Funktionen auf Listen: Filtern

„Alle Unentschieden“ und „alle Heimsiege“ aus einer Liste von Spielen – die beiden Funktionen unterscheiden sich nur in der Bedingung. Also wird die Bedingung (ein Prädikat) zum Parameter:

; Alle Elemente behalten, für die p? gilt
(: extract-list ((%a -> boolean) (list-of %a) -> (list-of %a)))

(check-expect (extract-list even? (list 1 2 3 4)) (list 2 4))

(define extract-list
  (lambda (p? list)
    (cond
      ((empty? list) empty)
      ((cons? list)
       (if (p? (first list))
           (cons (first list) (extract-list p? (rest list)))
           (extract-list p? (rest list)))))))

Eingebaut heißt das filter – Reihenfolge: erst das Prädikat, dann die Liste.

(define game-draw? (lambda (g) (= (home-points g) 1)))
(filter game-draw? day1)                ; alle Unentschieden am 1. Spieltag

Anonyme Funktionen: Statt für jede Bedingung eine Funktion mit Namen zu definieren, schreibt man das lambda direkt hin:

; Alle Spiele, an denen Hamburg beteiligt ist
(filter (lambda (g)
          (or (string=? (game-home-team g) "Hamburg")
              (string=? (game-guest-team g) "Hamburg")))
        season)

9.3 Listen umwandeln: map

Jedes Element einer Liste in etwas anderes verwandeln – z. B. jedes Spiel in seine Gesamttorzahl:

(: list-apply ((%a -> %b) (list-of %a) -> (list-of %b)))

(define list-apply
  (lambda (f list)
    (cond
      ((empty? list) empty)
      ((cons? list)
       (cons (f (first list))
             (list-apply f (rest list)))))))

(define total-goals
  (lambda (g) (+ (game-home-goals g) (game-guest-goals g))))

(list-apply total-goals (list game1))   ; => (list 2)

Eingebaut: map – erst die Funktion, dann die Liste. (map (lambda (x) (* x x)) (list 1 2 3)) → (list 1 4 9).

Beachte die Signatur ((%a -> %b) (list-of %a) -> (list-of %b)): Die Elemente dürfen dabei ihre Sorte wechseln (Spiele → Zahlen).

9.4 Listen zusammenfalten: fold

list-sum und list-product unterscheiden sich nur im Basiswert (0 bzw. 1) und in der Verknüpfung (+ bzw. *). Beides wird zum Parameter:

(: list-fold (%a (%b %a -> %a) (list-of %b) -> %a))

(check-expect (list-fold 0 + (list 1 2 3 4)) 10)
(check-expect (list-fold 1 * (list 1 2 3 4)) 24)

(define list-fold
  (lambda (for-empty for-cons list)
    (cond
      ((empty? list) for-empty)
      ((cons? list)
       (for-cons (first list)
                 (list-fold for-empty for-cons (rest list)))))))

Was fold macht: Es ersetzt in der Liste jedes cons durch die Verknüpfung und das empty durch den Basiswert:

(list-fold 0 + (cons 1 (cons 2 (cons 3 empty))))
=             (+ 1    (+ 2    (+ 3    0)))
= 6

Eingebaut: fold – Reihenfolge Basiswert, Verknüpfung, Liste. Weitere Beispiele: (fold empty append (list (list 1 2) (list 3))) → (list 1 2 3) (Liste von Listen flachklopfen). Sogar map lässt sich mit fold schreiben.

9.5 Schönfinkeln (Currying)

Eine Funktion mit zwei Parametern kann man in eine Funktion mit einem Parameter verwandeln, die eine Funktion für den zweiten Parameter liefert. Benannt nach Moses Schönfinkel und Haskell Curry.

(: curry ((%a %b -> %c) -> (%a -> (%b -> %c))))
(define curry
  (lambda (f)
    (lambda (a)
      (lambda (b)
        (f a b)))))

(: uncurry ((%a -> (%b -> %c)) -> (%a %b -> %c)))
(define uncurry
  (lambda (f)
    (lambda (a b)
      ((f a) b))))

(define plus-5 ((curry +) 5))
(check-expect (plus-5 10) 15)
(check-expect ((uncurry (curry +)) 3 4) 7)

Nützlich mit filter und map: (filter ((curry plays-game?) "Hamburg") season) – dabei ist plays-game? eine Funktion (team game -> boolean), und ((curry plays-game?) "Hamburg") ergibt ein Prädikat für einzelne Spiele.

9.6 Lexikalische Bindung

Wenn derselbe Name an mehreren Stellen vorkommt – welcher ist gemeint? Regel: Von der Stelle aus nach außen durch die Klammern suchen; der erste Parameter oder die erste lokale Definition mit diesem Namen gewinnt. Findet man keinen, gilt die globale Definition, dann die eingebaute.

(define f
  (lambda (x)
    (define y (+ x 1))
    (lambda (x)          ; neues x – verdeckt das äußere
      (+ x y))))

((f 1) 2)   ; y = 1 + 1 = 2, inneres x = 2  =>  4

10.1 Zwischenergebnisse mitführen

Aufgabe: eine Liste umdrehen. Mit der normalen Schablone dreht man den Rest um und hängt das erste Element hinten an:

; Element hinten an eine Liste anhängen
(define append-element
  (lambda (list element)
    (cond
      ((empty? list) (cons element empty))
      ((cons? list)
       (cons (first list) (append-element (rest list) element))))))

; Liste umdrehen (langsam)
(define invert
  (lambda (list)
    (cond
      ((empty? list) empty)
      ((cons? list)
       (append-element (invert (rest list)) (first list))))))

Das funktioniert, ist aber langsam: append-element läuft jedes Mal die ganze Liste entlang. Bei n Elementen sind das etwa 1 + 2 + … + n = n(n+1)/2 Schritte – quadratisches Wachstum. Bei 10.000 Elementen rund 50 Millionen Schritte.

Mit Akkumulator: Man geht die Liste von vorne durch und legt jedes Element vorne auf einen zweiten Stapel (inverted). Vorne anhängen kostet nur einen Schritt:

(define invert-helper
  (lambda (list inverted)
    (cond
      ((empty? list) inverted)
      ((cons? list)
       (invert-helper (rest list)
                      (cons (first list) inverted))))))

(invert-helper (list 1 2 3) empty)   ; => (list 3 2 1)

10.2 Schablonen für Funktionen mit Akkumulator

Damit man keine extra Hilfsfunktion braucht, definiert man sie lokal im Rumpf. Beispiel Summe:

(: list-sum ((list-of number) -> number))

(check-expect (list-sum (list 1 2 3 4)) 10)

(define list-sum
  (lambda (list0)
    (define accumulate
      ; sum ist die Summe aller Elemente in list0 vor list
      (lambda (list sum)
        (cond
          ((empty? list) sum)
          ((cons? list)
           (accumulate (rest list) (+ (first list) sum))))))
    (accumulate list0 0)))

Die Namen: list0 ist die ganze ursprüngliche Liste, list der noch nicht bearbeitete Rest.

Die Invariante ist ein Kommentar, der genau sagt, was im Akkumulator steht – und zwar in jedem Schritt. Sie ist der wichtigste Teil, denn aus ihr folgt alles andere:

  • Startwert: Am Anfang wurde noch nichts verarbeitet → Summe von nichts = 0.

  • Neuer Akkumulator: Kommt (first list) dazu → (+ (first list) sum).

  • Ergebnis: Ist list leer, wurde alles verarbeitet → sum ist die Antwort.

Schablone „Listen als Eingabe, mit Akkumulator“

(define f
  (lambda (list0)
    (define accumulate
      ; Invariante: acc ist ... der Elemente zwischen list0 und list
      (lambda (list acc)
        (cond
          ((empty? list) ... acc ...)
          ((cons? list)
           (accumulate (rest list) (... (first list) ... acc ...))))))
    (accumulate list0 ...)))

Beachte: Im cons-Fall steht der rekursive Aufruf ganz außen – er ist nicht in ein + oder cons eingepackt.

10.3 Über natürliche Zahlen akkumulieren

Dasselbe Muster mit Zahlen statt Listen:

(define power
  (lambda (base exponent0)
    (define accumulate
      ; power ist base hoch (exponent0 - exponent)
      (lambda (exponent power)
        (cond
          ((zero? exponent) power)
          ((positive? exponent)
           (accumulate (- exponent 1) (* power base))))))
    (accumulate exponent0 1)))

Während exponent herunterzählt, wächst power. Startwert 1 = base⁰. Tipp: Bei + und * ist die Reihenfolge egal; bei vielen anderen Aufgaben muss man überlegen, ob man von 0 aufwärts oder von n abwärts zählt – so, wie man es auf Papier machen würde.

10.4 Aktienkurse analysieren

Aufgabe: Gegeben die Kurse einer Aktie an aufeinanderfolgenden Tagen. Was ist der größte Gewinn, wenn man an einem Tag kauft und an einem späteren Tag verkauft?

Beispiel: Kurse 5 2 7 3 9 5 1 → bei 2 kaufen, bei 9 verkaufen → Gewinn 7. „Maximum minus Minimum“ wäre falsch (9 − 1 = 8), weil die 1 erst nach der 9 kommt.

10.5 Kontext und Endrekursion

Vergleiche im Stepper (list-sum (list 1 2 3 4)) ohne und mit Akkumulator:

; ohne Akkumulator: die Additionen stapeln sich
(+ 1 (+ 2 (+ 3 (+ 4 0))))

; mit Akkumulator: nichts wartet
(accumulate (list 1 2 3 4) 0)
(accumulate (list 2 3 4) 1)
(accumulate (list 3 4) 3)
(accumulate (list 4) 6)
(accumulate empty 10)
10

  • Der Kontext eines Aufrufs ist das, was danach noch zu tun ist (ohne Akkumulator: „noch 1 addieren, noch 2 addieren …“). Der Kontext braucht Speicher.

  • Ein Endaufruf (tail call) hat keinen Kontext – danach ist nichts mehr zu tun. Ist er rekursiv, spricht man von Endrekursion.

  • So ein Ablauf heißt iterativ (wie eine Schleife). Die Lehrsprachen brauchen dafür keinen zusätzlichen Speicher; viele andere Sprachen leider schon.

10.6 Das Phänomen der umgedrehten Liste

Aufgabe: die geraden Zahlen einer Liste herausfiltern – mit Akkumulator:

(define evens
  (lambda (list0)
    (define accumulate
      ; evens enthält die geraden Zahlen zwischen list0 und list
      ;   in umgekehrter Reihenfolge
      (lambda (list evens)
        (cond
          ((empty? list) (reverse evens))      ; einmal am Ende umdrehen
          ((cons? list)
           (accumulate (rest list)
                       (if (even? (first list))
                           (cons (first list) evens)
                           evens))))))
    (accumulate list0 empty)))

(check-expect (evens (list 1 2 3 4 5 6)) (list 2 4 6))

Ohne das reverse käme (list 6 4 2) heraus: Jedes cons legt das Element nach vorne, also landet das zuerst gefundene hinten. Die genaue Invariante („in umgekehrter Reihenfolge“) zeigt, dass man einmal am Ende umdrehen muss – nicht in jedem Schritt (das wäre wieder quadratisch).

10.7 Listen iterativ zusammenfalten

Wie in Kapitel 9 kann man die Akkumulator-Schablone selbst zu einer Funktion höherer Ordnung machen:

(: list-fold-left ((list-of %a) %acc (%a %acc -> %acc) (%acc -> %b) -> %b))

(define list-fold-left
  (lambda (list0 start-acc next-acc final-acc->result)
    (define accumulate
      (lambda (list acc)
        (cond
          ((empty? list) (final-acc->result acc))
          ((cons? list)
           (accumulate (rest list) (next-acc (first list) acc))))))
    (accumulate list0 start-acc)))

(list-fold-left (list 1 2 3 4 5) 0 + (lambda (sum) sum))                ; => 15
(list-fold-left (list 1 2 3) empty cons (lambda (inverted) inverted))   ; => (list 3 2 1)

„Left“, weil die Liste von links nach rechts verarbeitet wird; fold aus Kapitel 9 arbeitet von rechts nach links.

11.8 Überfahren konkret

Steht das Auto auf einer Position? Gleiche Spur und Abstand höchstens eine halbe Autolänge:

  (lambda (car-pos pos)

           (if (car-on-position? car-pos (dillo-on-road-position d))
               (make-dillo-on-road (run-over-dillo (dillo-on-road-state d))
                                   (dillo-on-road-position d))

Eine Person hat einen Namen und zwei Elternteile. Ein Elternteil ist entweder wieder eine Person oder unbekannt (dort endet der Stammbaum):

  (lambda (name p)

        (parent-ancestor? name (person-parent-1 p))
        (parent-ancestor? name (person-parent-2 p)))))

(define parent-ancestor?
  (lambda (name par)
    (cond
      ((person? par) (ancestor? name par))
      ((unknown-parent? par) #f))))

12.3 Bäume fürs Suchen

In einer Liste muss man im schlimmsten Fall jedes Element anschauen, um festzustellen, dass etwas nicht drin ist. In einem sortierten Baum gilt an jedem Knoten: links nur Kleineres, rechts nur Größeres. Dann muss man an jedem Knoten nur in einen Teilbaum weitersuchen:

(: tree-member? (real (tree-of false real) -> boolean))

(check-expect (tree-member? 10 tree4) #t)
(check-expect (tree-member? 4 tree4) #f)

(define tree-member?
  (lambda (x tree)
    (cond
      ((node? tree)
       (cond
         ((= x (node-label tree)) #t)
         ((< x (node-label tree)) (tree-member? x (node-left-branch tree)))
         (else (tree-member? x (node-right-branch tree)))))
      (else #f))))

Suche nach 10 in tree4: 10 > 5 → rechts; 10 < 17 → links; 10 = 10 → gefunden. Nur 3 Vergleiche.

12.4 Sortierte Bäume herstellen

Damit der Baum sortiert bleibt, fügt man neue Werte immer an der „richtigen“ Stelle ein:

(: tree-insert (real (tree-of false real) -> (tree-of false real)))

(check-expect (tree-member? 4 (tree-insert 4 tree4)) #t)

(define tree-insert
  (lambda (v tree)
    (cond
      ((node? tree)
       (cond
         ((= v (node-label tree)) tree)                          ; schon drin
         ((< v (node-label tree))
          (make-node (node-label tree)
                     (tree-insert v (node-left-branch tree))     ; links einfügen
                     (node-right-branch tree)))
         (else
          (make-node (node-label tree)
                     (node-left-branch tree)
                     (tree-insert v (node-right-branch tree)))))) ; rechts einfügen
      (else (make-node v #f #f)))))                              ; neues Blatt

Wie immer wird nichts „verändert“: Es entsteht ein neuer Baum, der die unveränderten Teilbäume wiederverwendet.

12.7 Suchbäume balancieren

Fügt man sortierte Werte (1, 2, 3, 4, …) mit tree-insert ein, hängt alles nach rechts – der Baum entartet zu einer Liste, und der Geschwindigkeitsvorteil ist weg. Lösung (nach Stephen Adams, 1993): beim Einfügen gleich ausbalancieren.

  • Jeder Knoten speichert zusätzlich die Größe seines Teilbaums (Anzahl Knoten) – ein größenannotierter Baum. make-sized-node berechnet sie automatisch: 1 + Größe links + Größe rechts.

  • Ist eine Seite mehr als ratio = 5-mal so groß wie die andere, wird umgebaut (bei sehr kleinen Bäumen unter 2 Knoten nicht).

12.8 Ausbalancieren durch Rotation

Eine Rotation ordnet Knoten um, ohne die Sortierung zu zerstören. X, Y, Z sind Teilbäume.

Einfache Rotation (Baum ist rechtslastig, äußerer Teil Z ist groß):

;      a                    c
;     / \                  / \
;    X   c       =>       a   Z
;       / \              / \
;      Y   Z            X   Y

Doppelte Rotation (rechtslastig, aber der innere Teil unter c ist groß):

;      a                      b
;     / \                   /   \
;    X   c                 a     c
;       / \      =>       / \   / \
;      b   Z             X  Y1 Y2  Z
;     / \
;    Y1  Y2

In beiden Fällen gilt hinterher immer noch: Alles in X < a < alles in Y < c < alles in Z – der Baum bleibt sortiert, ist aber flacher. Entscheidung: Ist Y kleiner als Z, reicht die einfache Rotation, sonst die doppelte. Für linkslastige Bäume entsprechend gespiegelt.

13.1 Korrektheit und Tests

Wasser wird nie heißer als 100 °C. Das soll für jede Wärmemenge gelten (Funktion heat->temperature aus Kapitel 2):

(check-property
 (for-all ((heat real))
   (<= (heat->temperature heat) 100)))

Aufbau:

  • for-all nennt die Variablen und ihre Signaturen: ((heat real)) heißt „für alle reellen Zahlen heat“. Mehrere Variablen: ((a number) (b number)).

  • Der Rumpf ist ein Ausdruck, der #t liefern muss.

  • check-property führt die Prüfung aus.

Ist die Eigenschaft verletzt, meldet DrRacket z. B.: „Eigenschaft falsifizierbar mit heat = 206“ – also ein konkretes Gegenbeispiel.

13.2 Wie check-property funktioniert

check-property beweist nichts, es probiert aus: Es erzeugt etwa 100 Eingaben, die zur Signatur passen (große und kleine Zahlen, Grenzwerte, leere und lange Listen …), und prüft jede. Die Werte wirken zufällig, sind aber bei jedem Start gleich – ein Fehler lässt sich also reproduzieren.

Das Verfahren heißt Property-based Testing und stammt ursprünglich aus dem Werkzeug QuickCheck. Dass man Korrektheit im Allgemeinen gar nicht automatisch beweisen kann, zeigt der Satz von Rice – Stichproben sind deshalb ein guter Kompromiss.

13.3 Mehr Eigenschaften und inexakte Zahlen

Umkehrfunktion: temperature->heat soll heat->temperature rückgängig machen. Das gilt aber nur für Temperaturen bis 100 °C (darüber gibt es kein flüssiges Wasser). Mit ==> („impliziert“) schränkt man die Eingaben ein:

(check-property
 (for-all ((temp real))
   (==> (<= temp 100)
        (< (abs (- (heat->temperature (temperature->heat temp)) temp))
           0.0001))))

  • (==> Bedingung Eigenschaft): Die Eigenschaft muss nur gelten, wenn die Bedingung wahr ist. check-property erzeugt dann passende Fälle.

  • Inexakte Zahlen: Mit real erzeugt DrRacket auch gerundete Kommazahlen, erkennbar am Präfix #i (z. B. #i24.571428571428573). Dabei können winzige Rundungsfehler entstehen – deshalb oben der Vergleich mit Toleranz über abs statt mit =.

  • (expect a b) vergleicht zwei Werte beliebiger Sorte (wie check-expect, aber innerhalb einer Eigenschaft).

Vorsicht: Eine Eigenschaft kann man „austricksen“ – auch eine ganz andere (falsche) Funktion kann sie erfüllen. Eigenschaften ersetzen konkrete Beispiele deshalb nicht, sie ergänzen sie.

13.4 Relationale Probleme

Beim Sortieren gibt es manchmal mehrere richtige Ergebnisse: Sortiert man Bandmitglieder nach Geburtsjahr und zwei sind gleich alt, ist jede Reihenfolge der beiden richtig. Ein check-expect mit einem erwarteten Ergebnis passt dann nicht. Man spricht von einem relationalen Problem: Festgelegt ist die Beziehung zwischen Ein- und Ausgabe, nicht das genaue Ergebnis. Dafür eignen sich Eigenschaften:

; Ist eine Zahlenliste aufsteigend sortiert?
(define sorted?
  (lambda (list)
    (cond
      ((empty? list) #t)
      ((empty? (rest list)) #t)
      (else (and (<= (first list) (first (rest list)))
                 (sorted? (rest list)))))))

(check-property
 (for-all ((l (list-of integer)))
   (sorted? (sort-numbers l))))

(check-property
 (for-all ((l (list-of integer)))
   (= (length (sort-numbers l)) (length l))))

sort-numbers ist dabei die Sortierfunktion, die getestet wird (z. B. selbst geschrieben mit list-min aus Kapitel 6). Die zweite Eigenschaft ist nötig: Eine Funktion, die immer empty liefert, wäre sonst „sortiert“ – sie trickst die erste Eigenschaft aus.

13.5 Konstruktionsanleitungen für Testfälle?

Für Eigenschaften gibt es kein festes Rezept, aber drei bewährte Heuristiken:

  1. Wissen über das Problem nutzen: Was muss immer stimmen? (Temperatur ≤ 100, Ergebnis sortiert, Länge bleibt gleich …)

  2. Zusammenspiel mehrerer Funktionen: z. B. Umkehrfunktionen, Einfügen und Suchen („nach dem Einfügen ist das Element drin“).

  3. Austricksen: Eine einfache, aber falsche Funktion ausdenken, die die bisherigen Eigenschaften erfüllt – und dann eine Eigenschaft suchen, die sie entlarvt.

13.6 Suchbäume testen

Das balancierte Einfügen aus Kapitel 12 ist kompliziert – ideal für Eigenschaften. Man prüft mehrere Dinge getrennt, jeweils für Bäume, die aus beliebigen Zahlenlisten aufgebaut werden:

  • Ist der Baum ein korrekter Suchbaum (links kleiner, rechts größer)?

  • Stimmen die gespeicherten Größen?

  • Ist der Baum balanciert (keine Seite mehr als ratio-mal so groß)?

  • Ist jedes eingefügte Element auch drin?

(check-property
 (for-all ((elements (list-of natural)))
   (proper-sized-search-tree? (list->balanced-search-tree = < elements))))

Dabei fand check-property im Buch tatsächlich einen Fehler: Die Liste (list 1 1 3) verletzte die Balance-Formel bei sehr kleinen Bäumen. Lösung: kleine Bäume (weniger als 2 Knoten) gesondert behandeln.

13.7 Algebraische Eigenschaften

Viele Operationen haben dieselben „algebraischen“ Eigenschaften:

EigenschaftBedeutungBeispiel
AssoziativitätKlammerung egal: a ⊙ (b ⊙ c) = (a ⊙ b) ⊙ c+, *, concatenate, and, or
neutrales Elementn ändert nichts: a ⊙ n = a0 für +, 1 für *, empty für concatenate
KommutativitätReihenfolge egal: a ⊙ b = b ⊙ a+, * (aber nicht concatenate!)
(check-property
 (for-all ((a rational) (b rational) (c rational))
   (= (+ a (+ b c)) (+ (+ a b) c))))

(check-property
 (for-all ((a (list-of number)))
   (expect (concatenate a empty) a)))

Achtung: Mit number statt rational schlägt die Assoziativität von + fehl – bei gerundeten Kommazahlen kann (a + b) + c minimal anders sein als a + (b + c).

Fachbegriffe: Eine Operation mit Signatur (s s -> s) heißt Kombinator. Ist sie assoziativ, bilden Signatur und Operation eine Halbgruppe; gibt es zusätzlich ein neutrales Element, ist es ein Monoid. Beispiel: Listen mit concatenate und empty.

13.8 Eigenschaften von Funktionen auf Listen

list-sum hat eine schöne Eigenschaft: Die Summe zweier aneinandergehängter Listen ist die Summe der Einzelsummen.

(check-property
 (for-all ((a (list-of rational)) (b (list-of rational)))
   (= (list-sum (concatenate a b))
      (+ (list-sum a) (list-sum b)))))

list-sum „übersetzt“ also concatenate in + (und empty in 0). Eine solche strukturerhaltende Abbildung heißt Homomorphismus.

13.9 Exkurs: Eigenschaften beweisen

Für sicherheitskritische Software (Flugzeuge, Medizin) reichen Stichproben nicht – dort beweist man Eigenschaften. Mit den Methoden aus Kapitel 8 kann man z. B. die Assoziativität von concatenate per Induktion über die erste Liste beweisen. Der Beweis folgt genau den Auswertungsschritten, die auch der Stepper zeigt. Für große Programme benutzt man spezielle Beweiswerkzeuge.

Kapitel 14: Exkurs – Der λ-Kalkül

✎ Übungen⌘ BefehleAa Begriffe⚠ Fehler

Der λ-Kalkül (Lambda-Kalkül) ist das mathematische Modell hinter lambda. Alonzo Church hat ihn in den 1930er Jahren erfunden; John McCarthy baute darauf 1958 die Sprache LISP, aus der Racket stammt. Das Erstaunliche: Der Kalkül kennt nur Funktionen – und trotzdem kann man darin alles programmieren, auch Zahlen, Wahrheitswerte und Rekursion.

14.1 Was hat ein alter Kalkül mit Programmieren zu tun?

Church wollte mit dem λ-Kalkül die Grundlagen der Mathematik untersuchen. McCarthy erkannte, dass er sich als Programmiersprache eignet (LISP = list processing). Peter Landin schlug ihn später als Basis für eine ganze Sprachfamilie vor („ISWIM“). Fast alle modernen Sprachen haben Ideen daraus übernommen – „Lambdas“ gibt es heute in Java, Python, JavaScript und C++. Übrigens: Das λ entstand vermutlich durch einen Satzfehler; weil frühe Computer kein λ darstellen konnten, schrieb man lambda aus.

14.2 Die Sprache des λ-Kalküls

Es gibt genau drei Arten von λ-Termen:

ArtSchreibweisein RacketBedeutung
Variablexxein Name
Applikation(e₀ e₁)(f a)Funktion e₀ auf Argument e₁ anwenden
Abstraktion(λv.e)(lambda (v) e)Funktion mit Parameter v und Rumpf e

Abkürzungen: Klammern lässt man weg, wo es eindeutig ist; der Rumpf einer Abstraktion reicht so weit wie möglich nach rechts; λxyz.e steht für λx.λy.λz.e (Schönfinkeln, Kapitel 9).

λfxy. f x ysteht fu¨r(λf.(λx.(λy.((f x) y))))\lambda f x y.\, f\,x\,y \quad\text{steht für}\quad (\lambda f.(\lambda x.(\lambda y.((f\,x)\,y))))λfxy.fxysteht fu¨r(λf.(λx.(λy.((fx)y))))

14.3 λ-Intuition

Abstraktionen sind Funktionen, Applikationen sind Funktionsaufrufe, Variablen sind Parameter. Weil es nur Funktionen mit einem Parameter gibt, werden mehrstellige Funktionen geschachtelt (wie curry). Zahlen und Wahrheitswerte gibt es nicht eingebaut – man muss sie aus Funktionen nachbauen (14.8).

14.4 Wie funktionieren Variablen?

Wie in Racket gilt lexikalische Bindung (Kapitel 9.6):

  • Eine Variable ist gebunden, wenn ein umschließendes λ sie als Parameter einführt, sonst frei. In λx.y ist x gebunden, y frei.

  • Ein Term ohne freie Variablen heißt abgeschlossen.

  • Substitution e[v ↦ f]: Ersetze in e alle freien Vorkommen von v durch f. Damit dabei keine Variable „eingefangen“ wird, benennt man gebundene Variablen notfalls vorher um.

14.5 Reduktion im λ-Kalkül

Rechnen heißt im λ-Kalkül: Terme nach Regeln umformen (reduzieren).

RegelWas passiertBeispiel
α-Reduktiongebundenen Parameter umbenennenλx.x → λy.y
β-ReduktionFunktion anwenden: Argument für Parameter einsetzen(λx.x) y → y
(λv. e)  f  →β  e[v↦f](\lambda v.\, e)\; f \;\rightarrow_\beta\; e[v \mapsto f](λv.e)f→β​e[v↦f]

Die β-Reduktion ist genau das, was der Stepper bei (tile s1 p1) zeigt: Parameter durch Argumente ersetzen. Ein Teilterm, der als Nächstes reduziert werden kann, heißt Redex. Oft gibt es mehrere Redexe gleichzeitig.

14.6 Normalformen

Ein Term, der sich nicht mehr β-reduzieren lässt, ist in Normalform – das „Ergebnis“. Der Satz von Church und Rosser garantiert: Egal in welcher Reihenfolge man reduziert – wenn man bei einer Normalform ankommt, ist es (bis auf Umbenennung) immer dieselbe. Aber nicht jeder Term hat eine:

(λx. x x) (λx. x x)  →β  (λx. x x) (λx. x x)  →β  …(\lambda x.\, x\,x)\,(\lambda x.\, x\,x) \;\rightarrow_\beta\; (\lambda x.\, x\,x)\,(\lambda x.\, x\,x) \;\rightarrow_\beta\; \dots(λx.xx)(λx.xx)→β​(λx.xx)(λx.xx)→β​…

Das ist eine Endlosschleife – das λ-Kalkül-Gegenstück zu einem Programm, das nie fertig wird.

14.7 Auswertungsstrategien

Eine Strategie legt fest, welcher Redex als Nächstes drankommt:

StrategieRegelEigenschaft
Linksaußen (normal order)äußersten linken Redex zuerstfindet immer eine Normalform, wenn es eine gibt
Call-by-Namewie Linksaußen, aber nicht unter λ rechnenArgumente erst bei Bedarf
Linksinnen (applicative order)Argumente zuerstspart doppelte Arbeit, terminiert nicht immer
Call-by-ValueArgumente zuerst, nicht unter λso arbeiten die Lehrsprachen

Im Stepper sieht man Call-by-Value: Bei (f (+ 1 2)) wird zuerst (+ 1 2) zu 3, erst dann wird f angewendet. Sprachen mit Call-by-Value heißen strikt; Haskell z. B. ist nicht-strikt („lazy“) und rechnet Argumente erst aus, wenn sie gebraucht werden.

14.8 Der λ-Kalkül als Programmiersprache

Wahrheitswerte als Funktionen: „true“ wählt von zwei Werten den ersten, „false“ den zweiten:

true=λxy. xfalse=λxy. yif=λtka. t k a\mathbf{true} = \lambda x y.\, x \qquad \mathbf{false} = \lambda x y.\, y \qquad \mathbf{if} = \lambda t k a.\, t\,k\,atrue=λxy.xfalse=λxy.yif=λtka.tka

Dann gilt if true e₁ e₂ →* e₁: true wählt die Konsequente.

Church-Zahlen: Die Zahl n ist die Funktion, die eine Funktion f n-mal anwendet:

⌈0⌉=λf.λx. x⌈1⌉=λf.λx. f x⌈2⌉=λf.λx. f (f x)\lceil 0 \rceil = \lambda f.\lambda x.\, x \qquad \lceil 1 \rceil = \lambda f.\lambda x.\, f\,x \qquad \lceil 2 \rceil = \lambda f.\lambda x.\, f\,(f\,x)⌈0⌉=λf.λx.x⌈1⌉=λf.λx.fx⌈2⌉=λf.λx.f(fx)

Dazu lassen sich Nachfolger (succ), Vorgänger (pred) und Nulltest (zerop) als Terme bauen.

Rekursion ohne Namen: Im λ-Kalkül gibt es kein define – wie kann eine Funktion sich selbst aufrufen? Der Fixpunktsatz sagt: Für jedes F gibt es ein X mit F X ≡ X. Der Y-Kombinator berechnet so ein X:

Y=λf. (λx. f (x x)) (λx. f (x x))\mathbf{Y} = \lambda f.\,(\lambda x.\, f\,(x\,x))\,(\lambda x.\, f\,(x\,x))Y=λf.(λx.f(xx))(λx.f(xx))

Damit lässt sich z. B. die Fakultät definieren: fac = Y FAC, und fac ⌈3⌉ →* ⌈6⌉. (In Racket mit Call-by-Value funktioniert die wörtliche Übersetzung von Y nicht – man muss den Selbstaufruf in ein zusätzliches lambda einpacken.)

Kapitel 15: Exkurs – Die SECD-Maschine

✎ Übungen⌘ BefehleAa Begriffe⚠ Fehler

Wie führt ein Computer eigentlich ein Racket-Programm aus? Der λ-Kalkül rechnet „von innen nach außen“ durch Umformen – ein echter Prozessor arbeitet dagegen Befehl für Befehl. Die SECD-Maschine (Peter Landin, 1964) ist eine gedachte Maschine, die genau diese Lücke schließt. In diesem Kapitel baut man einen kleinen Compiler (Programm → Maschinenbefehle) und eine virtuelle Maschine (führt die Befehle aus). Sprachebene: „Schreibe Dein Programm! – fortgeschritten“ (wegen quote und Symbolen).

15.1 Der angewandte λ-Kalkül

Der reine λ-Kalkül kennt nur Funktionen. Für die Maschine erweitert man ihn um Basiswerte (Zahlen, #t, #f) und Primitiva (eingebaute Operationen wie +). Eine neue Regel, die δ-Reduktion, wendet ein Primitivum an, sobald alle Argumente Werte sind:

(+ (- 5 3) 17)  →  (+ 2 17)  →  19

15.2 Die SECD-Maschine

Der Name kommt von den vier Teilen ihres Zustands:

TeilNameInhalt
SStack (Stapel)die zuletzt berechneten Werte, der neueste oben
EEnvironment (Umgebung)welche Variable welchen Wert hat
CCodedie Befehle, die noch auszuführen sind
DDump (Ablage)gesicherte (S, E, C)-Zustände, um nach einem Funktionsaufruf zurückzukehren

Befehle:

  • Basiswert → auf den Stapel legen.

  • Variable → Wert in der Umgebung nachschlagen und auf den Stapel legen.

  • prim → Primitivum auf die obersten Stapelwerte anwenden.

  • Abstraktion → eine Closure auf den Stapel legen: (Parameter, Code des Rumpfs, aktuelle Umgebung). Die Closure „merkt sich“ ihre Umgebung – genau das, was in Kapitel 9 plus-5 konnte.

  • ap → eine Closure auf ein Argument anwenden: aktuellen Zustand im Dump sichern, Rumpf mit erweiterter Umgebung ausführen.

Übersetzung eines Aufrufs: Erst die Funktion, dann das Argument, dann ap:

[ ⁣[ (e0  e1) ] ⁣]  =  [ ⁣[e0] ⁣]    [ ⁣[e1] ⁣]    ap[\![\, (e_0\; e_1) \,]\!] \;=\; [\![ e_0 ]\!]\;\; [\![ e_1 ]\!]\;\; \mathtt{ap}[[(e0​e1​)]]=[[e0​]][[e1​]]ap

Statt Variablen im Rumpf zu ersetzen (wie die β-Reduktion), schlägt die Maschine sie in der Umgebung nach – das ist viel effizienter.

15.3 Quote und Symbole

Um Programme als Daten zu verarbeiten, braucht man quote: 'x (kurz für (quote x)) liefert das, was dasteht, ohne es auszuwerten.

AusdruckErgebnisErklärung
'(1 2 3)(1 2 3)eine Liste, ohne list zu schreiben
'mikemikeein Symbol (wie ein Name, aber als Wert)
(symbol? 'mike)#tist das ein Symbol?
(equal? 'mike 'mike)#tSymbole vergleicht man mit equal?
'(+ 1 2)(+ 1 2)eine Liste aus dem Symbol + und zwei Zahlen – nicht 3!

Zahlen, Strings und #t/#f sind selbstquotierend: '5 ist dasselbe wie 5.

15.4 Datendefinitionen für den λ-Kalkül

Mit quote sehen λ-Terme aus wie Racket-Code – als verschachtelte Listen. Ein Term ist eins der folgenden: Symbol (Variable), Applikation, Abstraktion, primitive Applikation oder Basiswert. Die Fälle erkennt man mit Prädikaten:

; Ist der Term eine Abstraktion, also eine Liste, die mit lambda beginnt?
(define abstraction?
  (lambda (term)
    (and (cons? term)
         (equal? 'lambda (first term)))))

(abstraction? '(lambda (x) x))   ; => #t
(abstraction? '(f 1))            ; => #f

15.5 Datendefinition für Maschinensprache

Die Befehle werden zu Records:

(define-record ap make-ap ap?)                    ; Funktionsanwendung, keine Felder
(define-record prim make-prim prim?
  (prim-operator symbol)                          ; z. B. '+
  (prim-arity natural))                           ; Anzahl der Argumente
(define-record abst make-abst abst?
  (abst-variable symbol)                          ; Parameter
  (abst-code machine-code))                       ; Code des Rumpfs

; Ein Maschinenprogramm ist eine Liste von Befehlen
(define machine-code (signature (list-of instruction)))

15.6 Ein Compiler für die SECD-Maschine

term->machine-code übersetzt einen Term in eine Befehlsliste – mit einem cond-Zweig pro Term-Art (Schablone für gemischte Daten mit Selbstbezug):

(check-expect (term->machine-code '(+ 1 2))
              (list 1 2 (make-prim '+ 2)))

Gelesen: „Lege 1 auf den Stapel, lege 2 auf den Stapel, wende + auf die obersten 2 Werte an.“ Die Befehlslisten der Teilterme hängt man mit einer Hilfsfunktion append-lists aneinander (gebaut mit fold).

15.7 SECD-Code ausführen

Die virtuelle Maschine besteht aus Records für ihre Teile und einer Funktion pro Übergangsregel:

Funktion / RecordAufgabe
bindingVariable + Wert (Baustein der Umgebung)
closureParameter + Code + Umgebung
framegesicherter Stack + Umgebung + Code (im Dump)
secdder ganze Maschinenzustand (S, E, C, D)
secd-stepführt einen Befehl aus (ein cond-Zweig pro Regel)
secd-step*wiederholt secd-step, bis kein Code mehr übrig ist
eval-secdübersetzt einen Term, führt ihn aus und liefert den Wert
(eval-secd '(((lambda (x) (lambda (y) (+ x y))) 1) 2))   ; => 3

Ist das Ergebnis eine Funktion, liefert eval-secd das Symbol 'function.

15.8 Die endrekursive SECD-Maschine

Problem: Bei jedem ap wächst der Dump – auch bei Endaufrufen (Kapitel 10.5), nach denen eigentlich nichts mehr zu tun ist. Lösung: ein neuer Befehl tailap, der eine Closure aufruft, ohne einen Rahmen im Dump zu sichern. Der Compiler bekommt dazu zwei Übersetzungsfunktionen: eine für Terme mit Kontext (erzeugt ap) und eine für Terme ohne Kontext (erzeugt tailap). Damit läuft sogar die Endlosschleife ((λx.x x)(λx.x x)) ohne dass der Speicher wächst – genau wie Endrekursion in den Lehrsprachen.
